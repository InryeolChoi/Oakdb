# Oakdb 통신 규칙 (버전 1)

Oakdb 서버와 클라이언트가 TCP 위에서 주고받는 바이트의 참조 문서다. 왜 이렇게 정했는지는 `docs/design/0020-server-first-pass.md`와 접속별 트랜잭션의 `docs/design/0025-multi-client-transactions.md`에 있다. 정상 종료는 `docs/design/0028-graceful-shutdown.md`. 이 문서는 명령이 늘 때마다(#37, #38) 고친다. 구현은 `crates/oakdb-server/src/protocol.rs`.

## 1. 프레임

```
┌──────────────┬─────────┬──────────────────────┐
│ 길이 u32 BE  │ 명령 u8 │ 데이터 (길이 - 1 바이트) │
└──────────────┴─────────┴──────────────────────┘
```

- 모든 수는 **빅엔디언**이다.
- **길이**는 명령 1바이트 + 데이터의 바이트 수다. 길이 칸 자신(4바이트)은 세지 않는다.
- 길이는 **1 이상 16 MiB(16 777 216) 이하**. 0이면 `0x40`, 넘으면 본문을 읽지 않고 `0x41`을 보낸 뒤 접속을 끊는다.
- 길이는 **주장**일 뿐이다. 서버는 그만큼 미리 잡지 않고, 바이트가 실제로 오는 만큼 메모리를 늘린다.

## 2. 순서

```
클라이언트                        서버
  HELLO  ───────────────────────▶
         ◀───────────────────────  READY  (또는 ERROR 후 끊음)
  QUERY  ───────────────────────▶
         ◀───────────────────────  ROWS | AFFECTED | DONE | ERROR
  QUERY  ───────────────────────▶
         ◀───────────────────────  …
  (소켓 닫기)
```

- 접속 직후 서버가 먼저 거절할 수 있다: 허용 목록에 없는 주소(`0x46`), 접속 상한 초과(`0x45`). 이때 서버는 HELLO를 기다리지 않고 `ERROR`를 보낸 뒤 끊는다.
- 첫 프레임은 반드시 `HELLO`다. 그 뒤 `QUERY` 하나에 응답 하나가 **보낸 순서대로** 온다.
- **예외: 서버가 먼저 보내는 `ERROR`.** 인사 뒤에도 서버는 요청 없이 `ERROR` 하나를 보내고 끊을 수 있다. 지금은 노는 접속의 시간 제한 `0x47`·`0x48`(2-2절)과 서버 종료의 `0x49`(2-4절)다. 클라이언트는 이것을 **다음 요청의 응답 자리**에서 읽게 된다. 그래서 응답 대신 끊는 코드(6절의 "끊음")가 오면 보낸 요청은 실행되지 않은 것이고, 그 뒤에는 아무것도 오지 않는다.
- 응답을 받기 전에 다음 요청을 보내는 것(파이프라이닝)은 **약속하지 않는다.** 서버가 순서대로 읽으므로 지금은 동작하지만, 의지하지 말 것.
- 끝내기 명령은 없다. 소켓을 닫으면 끝이다.
- `QUERY` 하나는 SQL 문장 하나다. 서버는 **접속마다 세션 하나**를 두고, 트랜잭션은 그 세션에 산다(2-1절).

### 2-1. 트랜잭션 (#37)

- 트랜잭션 밖에서는 문장 하나가 트랜잭션 하나다(자동 커밋).
- `BEGIN`(또는 `BEGIN TRANSACTION`)이 `DONE`으로 답하면 그 접속에 트랜잭션이 열린다. 그 뒤의 문장은 그 트랜잭션 안에서 돌고, 다른 접속에는 **커밋 전까지 보이지 않는다.** 트랜잭션은 `BEGIN` 때 커밋된 것만 본다(스냅샷).
- **클라이언트는 묻지 않고 계산한다.** 통신 규칙에는 상태 바이트가 없다. 규칙은 넷뿐이다.
  1. `BEGIN`이 `DONE`이면 트랜잭션 중이 된다. 다른 응답이면 그대로다.
  2. `COMMIT`/`ROLLBACK`은 **어떤 응답이든** 트랜잭션을 끝낸다(`0x20` 충돌, `0x25`도 끝남. `0x0B`면 원래 없었음).
  3. 그 밖의 문장은 상태를 바꾸지 않는다. 트랜잭션 안의 문장이 실패하면 **그 문장만** 없던 일이 되고 트랜잭션은 열린 채다.
  4. 접속이 끊기면(어느 쪽이 끊었든) 트랜잭션은 없다. 서버가 롤백했다.
  
  "BEGIN인가"는 문장 전체가 `BEGIN [TRANSACTION] [;]`로 읽힐 때만이다. `COMMIT now`처럼 파서가 거절하는 문장은 `COMMIT`이 아니다(`0x02`, 트랜잭션은 열린 채). Rust 클라이언트는 `oakdb_sql::transaction_command`로 같은 판정을 하고 `Client::in_transaction()`으로 알려 준다.
- 접속이 끝나는 모든 경우에 열린 트랜잭션은 **롤백**된다.

| 접속이 끝나는 경우 | 트랜잭션 |
|---|---|
| 클라이언트가 소켓을 닫음, 프레임 도중에 끊김 | 롤백 |
| 깨진 프레임으로 서버가 끊음 (`0x40`, `0x41`) | 롤백 |
| 서버 스레드 패닉 (`0x7F`) | 롤백 |
| 트랜잭션 중 너무 오래 놂 (`0x47`, 2-2절) | 롤백한 뒤 알리고 끊음 |
| 서버가 정상 종료함 (`0x49`, 2-4절) | 유예 시간 안에 마치지 못했으면 롤백한 뒤 알리고 끊음 |
| 서버 프로세스가 죽음 | 미커밋 쓰기는 메모리에만 있었으므로 다시 띄우면 없음 |
| **`COMMIT`을 보낸 뒤 응답 전에 끊김** | **결과를 모른다.** 커밋되었을 수도, 아닐 수도 있다. 모든 DB가 같다. 다시 접속해 확인할 것 |

### 2-2. 노는 접속의 시간 제한

| 상태 | 제한 | 넘으면 |
|---|---|---|
| 트랜잭션 중 | `oakdb serve --idle-in-transaction-timeout <초>`, 기본 **60초**, `0`이면 없음 | 롤백 → `ERROR 0x47` → 끊음 |
| 트랜잭션 밖 | `--idle-timeout <초>`, 기본 **없음(0)** | `ERROR 0x48` → 끊음 |

- "논다"는 **다음 프레임의 첫 바이트를 기다리는 시간**이다. 문장을 실행하는 시간(커밋의 sync 포함)은 세지 않는다.
- 프레임을 반쯤 보내고 멈춰도 같은 제한으로 끊는다(읽기 한 번마다의 제한).
- 응답을 쓰는데 클라이언트가 읽지 않아도 같은 제한으로 포기하고 끊는다(롤백).
- 아주 천천히 흘려보내는 클라이언트(제한보다 짧은 간격으로 1바이트씩)는 아직 막지 않는다.
- **클라이언트 쪽 시간 제한은 서버와 따로다.** 클라이언트가 응답을 기다리다 제 시간 제한으로 포기하면 그 접속은 버려야 한다(늦게 온 응답이 다음 요청의 답으로 읽힌다). Rust `Client`는 그때 소켓을 닫고 `in_transaction()`을 `false`로 한다. 다만 서버는 실행 중이던 문장을 마치고 닫힘을 볼 때까지 트랜잭션을 잠깐 더 쥐고 있을 수 있고, 시간 초과된 것이 `COMMIT`이었다면 결과를 모른다(2-1절 표 마지막 줄).
- 서버는 트랜잭션이 `--warn-transaction-age <초>`(기본 300초)보다 오래 열려 있으면 로그에 경고를 한 번 남긴다. 오래 사는 트랜잭션은 옛 페이지와 충돌 기록을 메모리에 붙잡는다.

### 2-4. 서버가 종료할 때 (#38)

`oakdb serve`는 SIGINT(Ctrl-C)나 SIGTERM을 받으면 정상 종료한다.

| 그때 접속이 | 받는 것 |
|---|---|
| 아직 접속 대기열에 있음, 또는 HELLO 전 | `ERROR 0x49` → 끊음 |
| 트랜잭션 밖에서 노는 중 | `ERROR 0x49` (요청 없이 먼저 옴) → 끊음 |
| 문장을 실행 중 (커밋 sync 포함) | 그 문장의 응답, 이어서 `ERROR 0x49` → 끊음 |
| 트랜잭션 중 | 유예 시간(`--shutdown-grace`, 기본 10초) 동안 문장을 계속 보낼 수 있다. `COMMIT`/`ROLLBACK`의 응답 뒤 `0x49`. 유예가 끝나면 롤백 → `0x49` |
| 프레임(HELLO 포함)을 반쯤 보낸 채 | 위의 끊는 때(트랜잭션 밖이면 바로, 안이면 유예 끝)에서 100 ms 안에 나머지가 오면 그 문장을 실행하고 응답한다. 안 오면 (롤백 →) `0x49` → 끊음 |
| 종료 뒤 새로 접속 | 운영체제가 거절(`connection refused`) |

약속:

- **`0x49`는 요청 없이 올 수 있다.** 요청을 보내고 `0x49`를 받으면 그것이 그 요청의 답이다.
- **`0x49`가 답한 요청은 실행되지 않았다.** 서버는 실행한 문장의 응답을 반드시 먼저 보낸다. `COMMIT`의 답이 `0x49`면 커밋되지 않았다.
- **`0x49`를 받으면 열린 트랜잭션은 없다.** 롤백되었거나 직전 응답으로 이미 끝났다.
- 정상 종료에서는 응답 없이 끊기는 요청이 없다. 두 번째 신호(강제 종료), 유예 + 5초가 지나도 끝나지 않는 문장, `kill -9`일 때만 2-1절의 "결과를 모른다"가 생긴다.
- 정상 종료(종료 코드 0) 뒤에는 WAL이 비어 있어 다시 띄울 때 재생할 것이 없다.

`oakdb serve`의 종료 코드: `0` 정상 종료(롤백이 있었어도), `1` 시작 실패 또는 마지막 체크포인트 실패 또는 유예 + 5초 뒤에도 실행 중인 문장이 있음(다음 시작이 WAL을 재생), `2` 명령줄 오류, `130`/`143` 종료 중 두 번째 SIGINT/SIGTERM으로 바로 멈춤.

### 2-3. 트랜잭션 안에서 오류가 오면

| 오류 | 트랜잭션은 | 클라이언트가 할 일 |
|---|---|---|
| `0x01–0x0A`, `0x1F` 문장 오류 | **열린 채**, 그 문장만 없던 일 | 고쳐서 다시, 또는 `ROLLBACK` |
| `0x0B` 상태 오류 | 그대로 | 상태를 다시 맞춤 |
| `0x20` 충돌 (`COMMIT`에서) | **끝남, 아무것도 안 씀** | **`BEGIN`부터** 다시 |
| `0x20` 충돌 (자동 커밋 문장) | 그 문장의 트랜잭션이 끝남 | 그 문장만 다시 |
| `0x25` 결과 모름 (`COMMIT`에서) | 끝남 | 서버를 다시 띄우고 확인 |
| `0x26` 엔진 멈춤 | 열린 채(어차피 커밋 불가) | 서버를 다시 띄움 |
| `0x47`, `0x49`, `0x7F` (끊김) | 롤백됨 | 다시 접속해 `BEGIN`부터 (`0x49`면 서버가 다시 뜬 뒤) |

## 3. 명령

응답은 맨 앞 비트가 켜져 있다(`0x80` 이상).

| 값 | 이름 | 방향 | 데이터 |
|---|---|---|---|
| `0x01` | `HELLO` | → 서버 | 매직 `4f 41 4b 44 42`("OAKDB") + 버전 u16. 지금 버전은 `00 01` |
| `0x02` | `QUERY` | → 서버 | SQL 문장 하나, UTF-8. 끝 `;`는 있어도 없어도 됨 |
| `0x81` | `READY` | ← 서버 | 서버 버전 u16 |
| `0x82` | `ROWS` | ← 서버 | 4절 |
| `0x83` | `AFFECTED` | ← 서버 | 바뀐 행 수 u64 |
| `0x84` | `DONE` | ← 서버 | 없음 |
| `0x85` | `ERROR` | ← 서버 | 오류 코드 u8 + 메시지 UTF-8(프레임 끝까지) |

## 4. `ROWS`

```
열 개수 u16
열마다:     이름 길이 u16, 이름 UTF-8
행 개수 u32
행마다, 열마다 값 하나:
  00                         NULL
  01  i64 (8바이트)           INTEGER
  02  길이 u32 + UTF-8        TEXT
  03  길이 u32 + 바이트        BLOB
```

행마다 값의 개수는 열 개수와 같아서 따로 적지 않는다. 열이 0개면 행도 0개여야 한다. 결과 전체가 프레임 하나에 들어가야 하며, 16 MiB를 넘거나 길이가 제 칸(u16·u32)에 들어가지 않으면 `ERROR 0x44`가 대신 온다(접속은 유지). 잘라서 보내는 일은 없다.

## 5. 예

`SELECT name FROM users WHERE id = 1` 과 그 결과 `('kim')`:

```
→ 00 00 00 08 | 01 | 4f 41 4b 44 42 | 00 01                      HELLO 버전 1
← 00 00 00 03 | 81 | 00 01                                       READY 버전 1
→ 00 00 00 24 | 02 | 53 45 4c 45 43 54 20 6e 61 6d 65 …          QUERY (SQL 35바이트)
← 00 00 00 15 | 82 | 00 01 | 00 04 6e 61 6d 65 | 00 00 00 01 | 02 00 00 00 03 6b 69 6d
                     열 1개   "name"              행 1개        TEXT 'kim'
→ 00 00 00 …  | 02 | "SELECT * FROM nope WHERE id = 1"
← 00 00 00 15 | 85 | 03 | "no such table: nope"                   ERROR 0x03
```

## 6. 오류 코드

범위: `0x01–0x1F` 문장이 잘못됨(고쳐서 다시), `0x20–0x3F` 엔진이 거절했거나 멈춤, `0x40–0x5F` 대화 규칙이 깨짐. 모르는 코드를 받으면 범위로 판단한다.

| 코드 | 뜻 | 접속 |
|---|---|---|
| `0x01` | 문법 오류 (메시지에 바이트 위치) | 유지 |
| `0x02` | 지원하지 않는 SQL | 유지 |
| `0x03` | 없는 표 | 유지 |
| `0x04` | 없는 열 | 유지 |
| `0x05` | 이미 있는 표 | 유지 |
| `0x06` | 같은 열을 두 번 씀 | 유지 |
| `0x07` | 행의 값 개수가 열 개수와 다름 | 유지 |
| `0x08` | 기본 키 중복 | 유지 |
| `0x09` | 값의 종류가 열과 다름, 또는 NULL 기본 키 | 유지 |
| `0x0A` | SQL 층이 저장한 표 정보·행을 읽을 수 없음 | 유지 |
| `0x0B` | 트랜잭션 상태에 맞지 않는 명령: 트랜잭션 중 `BEGIN`("transaction error: a transaction is already open; COMMIT or ROLLBACK it first"), 트랜잭션 밖 `COMMIT`/`ROLLBACK`("transaction error: no transaction is open"). 열린 트랜잭션은 그대로 | 유지 |
| `0x1F` | 위에 없는 문장 오류 | 유지 |
| `0x20` | 충돌: 다른 트랜잭션이 같은 키를 먼저 커밋함. **다시 실행하면 될 수 있다**: 자동 커밋 문장이면 그 문장만, `COMMIT`이면 `BEGIN`부터(2-3절) | 유지 |
| `0x21` | 키가 너무 김 (512바이트 초과) | 유지 |
| `0x22` | 값이 너무 김 | 유지 |
| `0x23` | 데이터 파일 손상 | 유지 |
| `0x24` | 파일 시스템 오류 | 유지 |
| `0x25` | 이 커밋 중 디스크가 실패: **남았는지 알 수 없음.** 엔진이 멈췄다 | 유지 |
| `0x26` | 엔진이 디스크 실패로 멈췄다. 서버를 다시 띄워야 한다(다시 열면 응답한 커밋은 모두 있다) | 유지 |
| `0x3F` | 위에 없는 엔진 오류 | 유지 |
| `0x40` | 깨진 프레임: 길이 0, 모르는 명령, 모양이 틀린 데이터, 두 번째 HELLO | **끊음** |
| `0x41` | 프레임이 16 MiB를 넘음 | **끊음** |
| `0x42` | 인사 실패: 첫 프레임이 HELLO가 아님, 매직이나 버전이 다름 | **끊음** |
| `0x43` | SQL이 UTF-8이 아님 | 유지 |
| `0x44` | 결과가 16 MiB를 넘거나 길이가 제 칸에 들어가지 않음 | 유지 |
| `0x45` | 접속 상한 초과 (인사 전에 옴) | **끊음** |
| `0x46` | 허용 목록에 없는 주소 (인사 전에 옴) | **끊음** |
| `0x47` | 트랜잭션 중 다음 문장을 너무 오래 기다림. 트랜잭션은 **이미 롤백됨** (2-2절) | **끊음** |
| `0x48` | 트랜잭션 밖에서 너무 오래 놂 (`--idle-timeout`을 켰을 때만) | **끊음** |
| `0x49` | 서버가 종료 중. 요청 없이 올 수 있고, 이것이 답한 요청은 실행되지 않았다. 열린 트랜잭션은 없다 (2-4절) | **끊음** |
| `0x7F` | 서버 내부 오류: 이 접속을 처리하던 스레드가 패닉함. 서버와 다른 접속은 그대로 | **끊음** |

## 7. 누가 접속할 수 있나

- 허용 목록이 없으면 서버는 **127.0.0.1에만** 열고, 같은 컴퓨터의 클라이언트만 받는다.
- `oakdb serve --allow 10.0.0.5 --allow 192.168.1.0/24` 또는 `--allow-file <파일>`(한 줄에 하나, `#` 주석)로 IPv4 주소·CIDR 블록을 허용한다. 루프백 밖의 항목이 하나라도 있으면 `0.0.0.0`에 열고, 목록에 없는 주소는 `0x46`으로 거절한다. 루프백은 항상 허용된다. IPv6는 아직 지원하지 않는다.
- **이것은 인증이 아니다.** IP 주소는 누구인지가 아니라 어디서 왔는지만 말한다. NAT 뒤의 모든 사람은 같은 주소로 보이고, 같은 네트워크 안에서는 주소를 흉내 낼 수 있다. 통신은 암호화되지 않는다. 허용된 주소의 클라이언트는 모든 표를 읽고 고칠 수 있다. 믿을 수 있는 네트워크에만 열 것.
