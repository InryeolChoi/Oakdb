# Oakdb 통신 규칙 (버전 1)

Oakdb 서버와 클라이언트가 TCP 위에서 주고받는 바이트의 참조 문서다. 왜 이렇게 정했는지는 `docs/design/0020-server-first-pass.md`에 있다. 이 문서는 명령이 늘 때마다(#37, #38) 고친다. 구현은 `crates/oakdb-server/src/protocol.rs`.

## 1. 프레임

```
┌──────────────┬─────────┬──────────────────────┐
│ 길이 u32 BE  │ 명령 u8 │ 데이터 (길이 - 1 바이트) │
└──────────────┴─────────┴──────────────────────┘
```

- 모든 수는 **빅엔디언**이다.
- **길이**는 명령 1바이트 + 데이터의 바이트 수다. 길이 칸 자신(4바이트)은 세지 않는다.
- 길이는 **1 이상 16 MiB(16 777 216) 이하**. 0이면 `0x40`, 넘으면 본문을 읽지 않고 `0x41`을 보낸 뒤 접속을 끊는다.
- 길이는 **주장**일 뿐이다. 서버는 그만큼 미리 잡지 않고, 바이트가 실제로 오는 만큼 메모리를 늘린다.

## 2. 순서

```
클라이언트                        서버
  HELLO  ───────────────────────▶
         ◀───────────────────────  READY  (또는 ERROR 후 끊음)
  QUERY  ───────────────────────▶
         ◀───────────────────────  ROWS | AFFECTED | DONE | ERROR
  QUERY  ───────────────────────▶
         ◀───────────────────────  …
  (소켓 닫기)
```

- 접속 직후 서버가 먼저 거절할 수 있다: 허용 목록에 없는 주소(`0x46`), 접속 상한 초과(`0x45`). 이때 서버는 HELLO를 기다리지 않고 `ERROR`를 보낸 뒤 끊는다.
- 첫 프레임은 반드시 `HELLO`다. 그 뒤 `QUERY` 하나에 응답 하나가 **보낸 순서대로** 온다.
- 응답을 받기 전에 다음 요청을 보내는 것(파이프라이닝)은 **약속하지 않는다.** 서버가 순서대로 읽으므로 지금은 동작하지만, 의지하지 말 것.
- 끝내기 명령은 없다. 소켓을 닫으면 끝이다.
- `QUERY` 하나는 SQL 문장 하나이고, 그 문장 하나가 트랜잭션 하나다(자동 커밋). 접속별 트랜잭션은 #37.

## 3. 명령

응답은 맨 앞 비트가 켜져 있다(`0x80` 이상).

| 값 | 이름 | 방향 | 데이터 |
|---|---|---|---|
| `0x01` | `HELLO` | → 서버 | 매직 `4f 41 4b 44 42`("OAKDB") + 버전 u16. 지금 버전은 `00 01` |
| `0x02` | `QUERY` | → 서버 | SQL 문장 하나, UTF-8. 끝 `;`는 있어도 없어도 됨 |
| `0x81` | `READY` | ← 서버 | 서버 버전 u16 |
| `0x82` | `ROWS` | ← 서버 | 4절 |
| `0x83` | `AFFECTED` | ← 서버 | 바뀐 행 수 u64 |
| `0x84` | `DONE` | ← 서버 | 없음 |
| `0x85` | `ERROR` | ← 서버 | 오류 코드 u8 + 메시지 UTF-8(프레임 끝까지) |

## 4. `ROWS`

```
열 개수 u16
열마다:     이름 길이 u16, 이름 UTF-8
행 개수 u32
행마다, 열마다 값 하나:
  00                         NULL
  01  i64 (8바이트)           INTEGER
  02  길이 u32 + UTF-8        TEXT
  03  길이 u32 + 바이트        BLOB
```

행마다 값의 개수는 열 개수와 같아서 따로 적지 않는다. 열이 0개면 행도 0개여야 한다. 결과 전체가 프레임 하나에 들어가야 하며, 16 MiB를 넘거나 길이가 제 칸(u16·u32)에 들어가지 않으면 `ERROR 0x44`가 대신 온다(접속은 유지). 잘라서 보내는 일은 없다.

## 5. 예

`SELECT name FROM users WHERE id = 1` 과 그 결과 `('kim')`:

```
→ 00 00 00 08 | 01 | 4f 41 4b 44 42 | 00 01                      HELLO 버전 1
← 00 00 00 03 | 81 | 00 01                                       READY 버전 1
→ 00 00 00 24 | 02 | 53 45 4c 45 43 54 20 6e 61 6d 65 …          QUERY (SQL 35바이트)
← 00 00 00 15 | 82 | 00 01 | 00 04 6e 61 6d 65 | 00 00 00 01 | 02 00 00 00 03 6b 69 6d
                     열 1개   "name"              행 1개        TEXT 'kim'
→ 00 00 00 …  | 02 | "SELECT * FROM nope WHERE id = 1"
← 00 00 00 15 | 85 | 03 | "no such table: nope"                   ERROR 0x03
```

## 6. 오류 코드

범위: `0x01–0x1F` 문장이 잘못됨(고쳐서 다시), `0x20–0x3F` 엔진이 거절했거나 멈춤, `0x40–0x5F` 대화 규칙이 깨짐. 모르는 코드를 받으면 범위로 판단한다.

| 코드 | 뜻 | 접속 |
|---|---|---|
| `0x01` | 문법 오류 (메시지에 바이트 위치) | 유지 |
| `0x02` | 지원하지 않는 SQL | 유지 |
| `0x03` | 없는 표 | 유지 |
| `0x04` | 없는 열 | 유지 |
| `0x05` | 이미 있는 표 | 유지 |
| `0x06` | 같은 열을 두 번 씀 | 유지 |
| `0x07` | 행의 값 개수가 열 개수와 다름 | 유지 |
| `0x08` | 기본 키 중복 | 유지 |
| `0x09` | 값의 종류가 열과 다름, 또는 NULL 기본 키 | 유지 |
| `0x0A` | SQL 층이 저장한 표 정보·행을 읽을 수 없음 | 유지 |
| `0x1F` | 위에 없는 문장 오류 | 유지 |
| `0x20` | 충돌: 다른 트랜잭션이 같은 키를 먼저 커밋함. **다시 실행하면 될 수 있다** | 유지 |
| `0x21` | 키가 너무 김 (512바이트 초과) | 유지 |
| `0x22` | 값이 너무 김 | 유지 |
| `0x23` | 데이터 파일 손상 | 유지 |
| `0x24` | 파일 시스템 오류 | 유지 |
| `0x25` | 이 커밋 중 디스크가 실패: **남았는지 알 수 없음.** 엔진이 멈췄다 | 유지 |
| `0x26` | 엔진이 디스크 실패로 멈췄다. 서버를 다시 띄워야 한다(다시 열면 응답한 커밋은 모두 있다) | 유지 |
| `0x3F` | 위에 없는 엔진 오류 | 유지 |
| `0x40` | 깨진 프레임: 길이 0, 모르는 명령, 모양이 틀린 데이터, 두 번째 HELLO | **끊음** |
| `0x41` | 프레임이 16 MiB를 넘음 | **끊음** |
| `0x42` | 인사 실패: 첫 프레임이 HELLO가 아님, 매직이나 버전이 다름 | **끊음** |
| `0x43` | SQL이 UTF-8이 아님 | 유지 |
| `0x44` | 결과가 16 MiB를 넘거나 길이가 제 칸에 들어가지 않음 | 유지 |
| `0x45` | 접속 상한 초과 (인사 전에 옴) | **끊음** |
| `0x46` | 허용 목록에 없는 주소 (인사 전에 옴) | **끊음** |
| `0x7F` | 서버 내부 오류: 이 접속을 처리하던 스레드가 패닉함. 서버와 다른 접속은 그대로 | **끊음** |

## 7. 누가 접속할 수 있나

- 허용 목록이 없으면 서버는 **127.0.0.1에만** 열고, 같은 컴퓨터의 클라이언트만 받는다.
- `oakdb serve --allow 10.0.0.5 --allow 192.168.1.0/24` 또는 `--allow-file <파일>`(한 줄에 하나, `#` 주석)로 IPv4 주소·CIDR 블록을 허용한다. 루프백 밖의 항목이 하나라도 있으면 `0.0.0.0`에 열고, 목록에 없는 주소는 `0x46`으로 거절한다. 루프백은 항상 허용된다. IPv6는 아직 지원하지 않는다.
- **이것은 인증이 아니다.** IP 주소는 누구인지가 아니라 어디서 왔는지만 말한다. NAT 뒤의 모든 사람은 같은 주소로 보이고, 같은 네트워크 안에서는 주소를 흉내 낼 수 있다. 통신은 암호화되지 않는다. 허용된 주소의 클라이언트는 모든 표를 읽고 고칠 수 있다. 믿을 수 있는 네트워크에만 열 것.
