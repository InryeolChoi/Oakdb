# 구현 언어로 Rust를 선택

주력 프로젝트는 Java/Spring이지만, 이 DB는 Rust로 구현한다. 이 프로젝트의 목표는 저수준 시스템·Cloud/Infra·시스템 소프트웨어 직군에 지원할 포트폴리오를 만들고, DBMS 내부 동작을 이해하는 것이다. Rust의 소유권, 메모리 안전성, 동시성 모델(`Send`/`Sync`, 빌림 검사)은 저장 엔진과 동시성 제어를 설계할 때의 결정과 직접 맞닿아 있어, 그 연결을 이해하는 것 자체가 학습 목표다.

## Considered Options

- **Java/Kotlin**: 주력 스택과 같아 익숙하지만, GC와 바이트 단위 제어의 제약 때문에 시스템 소프트웨어 직군에 보여줄 신호가 약하다.
- **Go**: 생산성은 좋지만 이 프로젝트의 학습 목표(소유권 기반 동시성 이해)와 맞지 않는다.

## Consequences

- 코드는 대부분 AI가 작성하므로, 언어 학습 비용은 "작성"이 아니라 "읽고 설명하기"에 집중된다. 리뷰 단계에서 Rust 고유의 설계 선택을 반드시 짚고 넘어간다.
