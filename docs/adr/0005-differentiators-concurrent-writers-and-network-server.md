# SQLite와의 차별점: 동시 쓰기와 네트워크 서버

Oakdb는 SQLite와 같은 기본 구조(B+Tree 위의 관계형 DB)를 갖되, SQLite가 공식 문서에서 스스로 인정하는 한계 두 가지를 해결하는 데 집중한다.

1. **여러 트랜잭션의 동시 쓰기**: SQLite는 읽기는 동시에 여럿이 할 수 있지만 쓰기는 한 번에 하나만 허용한다([When to use](https://www.sqlite.org/whentouse.html), [WAL](https://www.sqlite.org/wal.html)). Oakdb에서는 서로 다른 행을 고치는 트랜잭션이 줄 서지 않고 동시에 진행된다.
2. **네트워크 너머 여러 클라이언트**: SQLite는 프로그램에 내장하는 라이브러리라, 네트워크로 여러 클라이언트가 붙는 경우에는 클라이언트/서버 DB를 쓰라고 안내한다([When to use](https://www.sqlite.org/whentouse.html)). Oakdb는 자체 서버 프로세스를 두고 여러 클라이언트가 네트워크로 접속한다.

두 가지는 서로 이어진다. 네트워크로 여러 클라이언트가 붙으면 동시 쓰기 상황이 생기고, "클라이언트 수를 늘릴 때 SQLite와 Oakdb의 쓰기 처리량" 비교 하나로 둘을 함께 증명할 수 있다.

## Considered Options

- **복제(replication)**: SQLite에 기본 기능이 없지만, 분산 영역이라 이번 범위에서 미루기로 한 결정(ADR 0002)과 겹쳐 제외했다.

## Consequences

- 엔진은 여전히 라이브러리 크레이트로 만들어 테스트와 장애 주입을 직접 하고, 그 위에 서버 크레이트를 둔다. 서버는 이제 선택이 아니라 필수다.
- B+Tree에서 여러 쓰기를 동시에 허용하려면 페이지 분할 중의 동시성 제어까지 직접 설계해야 한다. SQL 기능은 그만큼 최소한으로 줄인다.
