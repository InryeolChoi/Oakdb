# B+Tree 페이지 구조는 SQLite를 따르되, 페이지 체크섬을 더한다

Oakdb의 디스크 페이지 구조는 SQLite의 b-tree 페이지 형식을 기준으로 삼는다. Oakdb는 SQLite와 같은 기본 구조(B+Tree 위의 관계형 DB)에서 동시 쓰기와 네트워크 서버만 다르게 하는 것이 목표이므로(ADR 0004, 0005), 페이지 형식까지 맞춰 두면 벤치마크의 차이를 두 차별점에서 온 것으로 설명하기 쉽다. 또 검증된 설계와 공개 문서([SQLite Database File Format](https://www.sqlite.org/fileformat2.html))를 기준점으로 쓸 수 있다.

- **페이지 크기**: 4KB (SQLite 기본값).
- **페이지 안 배치**: 페이지 헤더 → 셀 포인터 배열(목차)이 앞에서부터 자라고, 셀 내용은 뒤에서부터 채운다. 지워진 공간은 빈 블록 목록으로 재사용한다.
- **큰 값**: 페이지에 다 들어가지 않는 값은 넘치는 부분을 overflow 페이지로 이어 붙인다.
- **페이지 체크섬 (SQLite와 다른 점)**: 모든 데이터 페이지에 CRC-32C 체크섬을 넣고, 페이지 번호도 섞어서 엉뚱한 위치에 쓰인 페이지까지 잡는다. PostgreSQL 18이 데이터 체크섬을 기본으로 켠 것과 같은 판단이다. 체크섬이 틀리면 항상 오류다.
- **표지(메타 페이지)**: 페이지 크기를 기록하고, 다른 크기로 만든 파일은 열지 않는다.
- **키 크기**: v1은 키를 512바이트로 제한한다. 키는 내부 페이지로 복사되므로 길면 트리가 높아진다. 값은 overflow 페이지로 크기 제한이 없다.

## Consequences

- 처음 추천한 "값 크기 상한"과 달리 overflow 페이지를 구현해야 하므로 B+Tree 작업이 늘어난다.
- 체크섬은 손상을 감지할 뿐 고치지는 못한다. 정전으로 반쯤 쓴 페이지는 체크포인트 중에만 생기며, 메타 슬롯이 가리키는 이전 체크포인트부터 WAL의 페이지 사본을 다시 적용해 고친다(ADR 0007). 체크포인트 이후 디스크가 조용히 망가진 페이지는 오류로 보고만 할 수 있다.
- 세부 배치(40바이트 헤더, 4바이트 슬롯, 리틀 엔디언 등)는 `docs/research/0005-btree-page-layout.md`의 권고를 따르되, 큰 값은 상한 대신 overflow 페이지로 한다.
- Oakdb에만 필요한 것(WAL 위치 등)은 SQLite 형식에 덧붙이고, 덧붙인 부분은 문서에 따로 적는다. 파일 자체를 SQLite와 호환시키지는 않는다.
