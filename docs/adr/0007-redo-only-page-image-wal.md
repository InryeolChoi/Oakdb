# 장애 복구: 페이지 전체 사본을 남기는 redo 전용 WAL

커밋 전까지 트리를 건드리지 않으므로(ADR 0006) 커밋되지 않은 내용은 디스크에 가지 않고, 되돌리기 로그가 필요 없다. 그래서 복구는 "다시하기"만 한다. 커밋 담당은 그룹 커밋 배치마다 바뀐 페이지의 **전체 사본**과 COMMIT 레코드를 WAL에 쓰고 디스크 기록을 한 번 한 뒤 응답한다. 데이터 파일은 체크포인트 때만 쓰고, 체크포인트 위치는 파일 앞의 메타 슬롯 두 개에 번갈아 기록한다. 재시작하면 유효한 메타 슬롯에서 시작해 WAL을 앞에서부터 다시 적용하고, 체크섬이 처음 깨진 레코드에서 멈춘다. 근거는 `docs/research/0004-btree-crash-recovery.md`.

## Considered Options

- **ARIES**: steal/no-force, undo, 보상 레코드까지 필요해 2개월 범위에 너무 크다.
- **롤백 저널(SQLite 기본)**: 그룹 커밋, 동시 쓰기와 맞지 않는다.
- **로그 + 복사형 체크포인트(WiredTiger 방식)**: 가능하지만 더 복잡하다.

## Consequences

- 반쯤 쓴 페이지는 체크섬으로 감지하고, 이전 체크포인트부터 WAL을 다시 적용해 복구한다. 메타 슬롯이 깨지면 다른 슬롯을 쓴다.
- 디스크 기록이 실패하면 재시도하지 않고 엔진을 정지시킨다. 그 배치의 클라이언트에는 "결과를 알 수 없음" 오류를 돌려준다. 짧은 쓰기와 디스크 공간 부족도 같은 방식으로 다룬다.
- 작은 변경도 4KB 페이지 전체를 로그에 쓰므로 WAL이 커진다. 벤치마크로 확인하고, 필요하면 PostgreSQL처럼 체크포인트 후 첫 변경에만 전체 사본을 쓰는 방식으로 줄인다.
