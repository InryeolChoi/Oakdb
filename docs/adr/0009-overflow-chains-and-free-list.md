# 긴 값은 통째로 overflow 사슬에, 빈 페이지는 사슬 목록으로

키와 값을 합쳐 1006바이트(`MAX_ENTRY_LEN`)가 넘으면 **값 전체**를 overflow 페이지 사슬에 쓴다. 리프 셀에는 첫 페이지 번호(u64)와 값 길이(u32)만 남기고, 셀의 `value_len` 맨 위 비트로 이를 표시한다. 값은 u32가 담는 만큼, 약 4GiB(`MAX_VALUE_LEN`)까지 받는다. 쓰지 않게 된 페이지(overflow든 트리든)는 **빈 페이지 사슬**에 넣는다. 메타 페이지에 첫 빈 페이지와 빈 페이지 수를 적고, 각 빈 페이지에 다음 빈 페이지를 적는다. 새 페이지는 파일을 늘리기 전에 이 목록에서 꺼낸다. 열 때는 모든 페이지가 트리, 값 하나의 사슬, 빈 페이지 목록 중 정확히 한 곳에만 속하는지 확인한다. 파일 형식 버전은 2가 된다. 근거와 세부는 `docs/design/0006-overflow.md`.

이 결정은 ADR 0008의 두 문장을 고친다. "넘치는 **부분**을 overflow 페이지로"는 "값 전체를"로, "값은 크기 제한이 없다"는 "u32가 담는 만큼"으로 바뀐다. 0008에도 같은 내용을 적었다.

## Considered Options

- **앞부분은 리프에, 나머지만 overflow (SQLite)**: 엔진은 값을 늘 통째로 읽으니 앞부분을 남겨 얻는 게 없다. 값이 두 곳에 나뉘어 코드만 복잡해진다.
- **별도 테이블 (PostgreSQL TOAST)**: 테이블 개념이 아직 없다.
- **목록 페이지에 빈 페이지 번호를 몰아 적기 (SQLite 트렁크)**: 지울 때 고쳐 쓰는 페이지가 적다. 대신 코드와 테스트가 는다. 벤치마크에서 단순 사슬이 문제가 될 때 바꾼다.
- **목록을 파일에 적지 않고 열 때 계산**: 페이지를 그때그때 디스크에서 읽게 되면 열 때 파일 전체를 훑어야 한다.
- **값 크기에 따로 상한 (예: 16MB)**: 한번 정하면 되돌리기 어려운 사용자 약속이 된다. u32 한계는 형식이 담을 수 있는 만큼이라 ADR 0008의 "제한 없음"에 가장 가깝다.

## Consequences

- 값을 지우거나 덮어쓰면 그 값의 overflow 페이지마다 빈 페이지 한 장을 쓴다. 100KB면 26장이다. WAL이 페이지 전체 사본을 남기면(ADR 0007) 로그도 그만큼 는다.
- 빈 페이지는 0으로 덮어쓰므로, 지운 긴 값의 바이트는 파일에 남지 않는다.
- 페이지를 재사용하므로 트리 깊이 상한(64)의 근거를 페이지 수에서 분할 횟수로 바꿨다.
- 스냅샷이 읽고 있는 페이지를 재사용하면 안 된다. 지금은 모든 페이지가 메모리의 `Arc`라 안전하다. 페이지 캐시와 스냅샷(#25)에서 재사용을 미루는 규칙이 필요하다.
- 버전 1 파일은 열지 않는다.
- 이 ADR은 이슈 #43이 다룰 기본 파일 형식(메타 페이지 위치, 리틀 엔디언, magic, 슬롯 길이)과는 별개다. #43은 다음 번호로 쓴다.
