# 0012. 서버 정상 종료 — 틱의 CPU, 다시 시작 시간 (참고 측정)

이슈 #38, 설계 `docs/design/0028-graceful-shutdown.md` Q13. **성능 주장이 없는 티켓이라 A/B 가설 검정은 하지 않는다.** 아래는 설계가 "측정해서 기록"하기로 한 두 값의 참고 기록이다.

도우미: `crates/oakdb-server/examples/shutdown_faults.rs`. Apple M3, macOS 27.0.1, APFS, release 빌드. Linux 값은 재지 않았다.

```
cargo build --release -p oakdb-server --bin oakdb --example shutdown_faults
ulimit -n 4096
target/release/examples/shutdown_faults tick 512 10
target/release/examples/shutdown_faults restart 5
```

## 1. 첫 바이트 틱의 CPU

**쉽게 말하면**: 노는 접속 스레드는 이제 100 ms마다 한 번 깨어나 "종료 중인가?"를 본다(설계 Q5-W2). 경비원이 10분마다 순찰하는 대신 0.1초마다 문을 흘끗 보는 셈이다. 손님이 512명일 때 그 흘끗이 얼마나 드나.

방법: `oakdb serve`를 띄우고, 인사(HELLO/READY)만 마친 노는 접속을 N개 열어 10초 둔 뒤 SIGTERM. 서버 프로세스의 CPU 시간(사용자 + 커널)을 `getrusage(RUSAGE_CHILDREN)`로 잰다.

| 노는 접속 | 10초 동안 서버 CPU | 코어 하나 대비 | 초당 깨어남 |
|---|---|---|---|
| 0 | 0.004 s | 0.04% | 0 |
| 512 | 0.446 s | **4.5%** | 약 5 120 |

- 깨어남 한 번에 약 **87 µs**의 CPU(0.446 s ÷ 51 200번). `recv` 시간 초과 하나와 스레드 깨우기·재우기다.
- 512개가 모두 놀 때 코어 하나의 4.5%다. 설계가 "나쁘면 250 ms"로 정해 둔 기준을 넘는다고 보지는 않았다. 노는 접속 512개는 이 서버의 상한이고, 그때도 나머지 95%는 남는다. 다만 **공짜는 아니다**는 것을 숫자로 남긴다. 틱을 250 ms로 늘리면 약 1.8%가 되는 대신 종료가 최대 250 ms 늦게 알려진다.
- 문장마다 읽기 시간 제한을 두 번 더 건다(틱 ↔ 프레임 나머지). `setsockopt` 두 번으로 µs 단위라 따로 재지 않았다. 자동 커밋 왕복의 비교가 필요해지면 벤치마크 0009의 도구로 A/A·A/B를 한다.
- 같은 측정에서 **SIGTERM → 끝까지 1.14초**가 걸렸다(접속 0개면 66 ms). 접속마다 `0x49`를 보낸 뒤 클라이언트가 닫기를 최대 1초(`LINGER`) 기다리는데, 이 측정의 클라이언트는 소켓을 닫지 않고 들고 있었기 때문이다. 보통의 클라이언트는 `0x49`를 읽고 바로 닫는다(실험 0021의 1: 중간값 105 ms).

## 2. 다시 시작 시간: 정상 종료 뒤 vs `kill -9` 뒤

**쉽게 말하면**: 장부 정리(마지막 체크포인트)를 하고 문을 닫으면, 다음 날 아침 가게를 여는 데 얼마나 빨라지나.

방법: 2 000바이트 BLOB 행을 자동 체크포인트(4 MiB) 바로 아래까지 넣어 WAL을 약 3.6 MiB로 만든 뒤 SIGTERM 또는 SIGKILL. 같은 디렉터리로 다시 띄워 "listening" 줄이 찍힐 때까지의 시간을 잰다(프로세스 시작 포함). 5번씩.

| 끝낸 방법 | 끝낼 때 WAL | 최소 | 중간값 | 최대 |
|---|---|---|---|---|
| SIGTERM (정상 종료, 마지막 체크포인트) | 20 B (헤더뿐) | 31 ms | **47 ms** | 53 ms |
| SIGKILL (WAL 3.6 MiB 재생) | 3 607 270 B | 41 ms | **60 ms** | 72 ms |

- 차이는 중간값 약 13 ms다. WAL이 4 MiB로 묶여 있어 재생이 오래 걸릴 수가 없다. **정상 종료가 주는 것은 빠른 시작보다 "재생할 것이 없다"는 확실함**이라는 설계의 말(0절 "명확함과 깔끔한 다음 시작")이 숫자로도 맞다.
