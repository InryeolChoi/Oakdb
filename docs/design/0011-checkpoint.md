# 0011. 체크포인트와 메타 슬롯 두 개 — 설계

이슈 #23, ADR 0007. 10번에서 커밋은 WAL(일지)에만 쓰게 됐다. 그래서 데이터 파일(장부)은 비어 있고, WAL은 끝없이 길어지고, 열 때마다 WAL을 처음부터 다시 읽는다. 이번 티켓은 **일지에 쌓인 페이지를 장부로 옮겨 적고 일지를 비운다.**

**비유**: 장부 맨 앞에 **표지 두 장**(메타 슬롯 A·B)이 있다. 표지에는 "장부가 몇 회차 정리까지 반영됐는지"를 적는다. 정리할 때마다 두 장 중 **오래된 쪽**에 새 회차를 적는다. 표지를 고쳐 쓰다 정전이 나 찢어져도 다른 한 장이 멀쩡하다. 일지 첫 장에도 "이 일지는 몇 회차부터 이어 쓴 것"이라고 적어서, 표지와 일지가 짝이 맞는지 확인한다.

## 사용자가 정한 것

| # | 질문 | 결정 |
|---|---|---|
| 1 | 언제 정리하나 | **커밋 뒤 WAL이 4MiB를 넘으면 그 커밋이 정리까지 하고 돌아온다.** 직접 부르는 `Db::checkpoint()`도 공개한다. 스레드는 #27 |
| 2 | WAL을 어떻게 비우나 | **길이 0으로 자르고 회차 머리말을 새로 쓴다.** 표지의 회차와 WAL 머리말의 회차가 다르면 그 WAL은 옛것이다. 완료 조건 1의 "WAL 파일이 지워지고"는 "WAL이 비워지고 sync된다"로 읽는다 |
| 3 | 표지 한 장이 깨지면 | **성한 표지 중 회차가 큰 쪽을 쓴다.** 그 회차가 WAL 머리말과 같을 때만 연다. 다르면 `Corrupt`로 거절한다. 형식 자리(magic·버전)가 깨진 표지도 똑같이 "깨진 표지"로 본다 |
| 4 | `oakdb.wal.cut` | **그대로 둔다.** 손상 조사용 파일이라 06번 보장("지운 값이 디스크에 남지 않음") 밖이다 |

## 구현하며 정한 것

| # | 무엇 | 결정 | 이유 |
|---|---|---|---|
| 5 | 닫기 | `close()`도 정리한다 | 닫고 다시 열면 WAL을 읽을 게 없다. 닫지 않고 끝난 프로세스는 정전과 같다 |
| 6 | 첫 정리 | 표지 **두 장 모두**에 1회차를 적는다 | 장부의 모든 페이지가 처음부터 체크섬을 가진다. 그 뒤로는 번갈아 쓴다 (2회차 → A, 3회차 → B, …) |
| 7 | 정리가 실패하면 | 엔진이 **멈춘다**. 그 뒤 커밋과 정리는 모두 오류를 낸다. 다시 열면 된다 | 새 표지가 디스크에 닿았는지 모르는 채 옛 회차 WAL에 계속 쓰면, 다시 열 때 그 커밋들이 "옛 WAL"로 버려진다. ADR 0007의 "기록 실패 시 정지"를 정리 경로에만 먼저 적용하고, 커밋 경로는 #24에서 한다 |

## 1. 순서

```text
① WAL에 있는 페이지(마지막 정리 뒤 바뀐 페이지)를 데이터 파일 제자리에 쓴다 → sync
② 새 회차 n+1의 메타 페이지를 슬롯 (n+1) % 2에 쓴다 (첫 정리는 두 슬롯 모두) → sync
③ WAL을 길이 0으로 자르고 sync → 머리말(회차 n+1)을 쓰고 sync
```

| 정전 시점 | 디스크에 남은 것 | 다시 열면 |
|---|---|---|
| ① 도중 | 반쯤 덮인 페이지, 표지 n, WAL n | 표지 n + WAL n 재생. 덮인 페이지는 **모두 WAL n에 있으니** 다시 덮인다 |
| ② 도중 | 찢어진 새 표지, 다른 표지 n, WAL n | 찢어진 표지는 체크섬으로 걸러진다. 위와 같다 |
| ② 뒤 ③ 전 | 표지 n+1, WAL n | WAL n은 옛것. 이미 장부에 다 옮겼으니 버리고 새 머리말을 쓴다 |
| ③ 도중 | 표지 n+1, 빈 WAL 또는 머리말 n+1 | 빈 WAL이면 머리말을 쓴다 |

페이지 이미지는 **통째 사본**이라 같은 것을 두 번 옮겨도 결과가 같다. 그래서 ①과 ②가 정전으로 반쯤 끝나도 다시 하면 된다.

**왜 자르기와 머리말 쓰기 사이에 sync를 한 번 더 하나.** 자르기가 디스크에 닿기 전에 머리말이 먼저 닿으면, 새 머리말 뒤에 옛 레코드가 그대로 붙어 있다. 사슬 체크섬이 머리말에서 시작하니 옛 레코드는 통과하지 못하지만, 그러면 "머리말이 찢어진 긴 WAL"과 구별할 수 없다. 자르기를 먼저 굳혀 두면 머리말이 찢어진 WAL은 언제나 머리말 길이(20바이트) 이하다.

## 2. 형식

### 메타 페이지 (형식 버전 4)

| 오프셋 | 크기 | 필드 |
|---|---|---|
| 0..52 | | 지금과 같음 (체크섬, magic, 버전, 페이지 크기, root, page_count, free_head, free_count) |
| 52..60 | u64 | **checkpoint**: 이 표지가 반영한 정리 회차 (1부터) |

버전 3 파일은 버전으로 거절한다. 누구의 데이터도 담고 있지 않다.

### WAL 머리말 (20바이트, 레코드 앞)

| 오프셋 | 크기 | 필드 |
|---|---|---|
| 0..8 | | magic `"oakwal\0\0"` |
| 8..16 | u64 | checkpoint: 이 WAL이 이어 쓰는 회차 (새 DB는 0) |
| 16..20 | u32 | crc = `crc32c_append(START, 앞 16바이트)` |

첫 레코드의 사슬은 `START`가 아니라 **머리말의 crc에서** 시작한다. 그래서 다른 회차의 WAL에서 온 레코드는 이 머리말 뒤에서 통과하지 못한다. 10번 설계 7절에서 미뤄 둔 "WAL 머리말" 숙제가 이것이다.

## 3. 열기

```text
데이터 파일 열기·잠금 → WAL 열기 → WAL 머리말과 레코드 재생
→ 표지 고르기
    데이터 파일이 비어 있지 않으면 슬롯 A·B를 각각 읽음 (형식 → 체크섬 → 필드)
    성한 슬롯 중 회차가 큰 쪽 = s (같으면 A)
→ WAL 머리말 h와 맞춰 보기
    s 있음, h = s       → s 위에 WAL 재생
    s 있음, h < s 또는 WAL이 머리말보다 짧음 → WAL은 옛것: 무시하고 머리말 s로 새로 씀
    s 있음, h > s       → 거절 (Corrupt): 최신 표지가 깨졌다
    s 없음, h = 0, 커밋 있음 → 장부는 무시하고 WAL만 재생 (첫 정리 도중 정전)
    s 없음, 데이터 파일 비어 있음, 커밋 없음 → 새 DB (WAL이 머리말 + 첫 커밋보다 길면 거절)
    그 밖                → 거절: 슬롯 A의 오류를 돌려줌
→ 데이터 파일이 표지 s의 page_count보다 짧으면 거절
→ 검사 끝. 이제 바꾸기: 꼬리 자르기(10번과 같음) 또는 WAL 새로 쓰기
```

- **머리말이 찢어진 WAL**: 머리말 길이(20바이트) **이하**라면 만들거나 비우는 도중의 정전이다. 머리말이 없는 것으로 보고 새로 쓴다. 그보다 길면 손상이라 거절한다. 뒤에 응답한 커밋이 있을 수 있어서다.
  - **정확히 20바이트인데 머리말이 틀린 경우** (리뷰 P1, 눈 가린 테스터): 머리말을 쓰다 정전이 나면 파일 길이만 먼저 닿고 내용은 0으로 남을 수 있다(Linux ext4 writeback, XFS 등). 처음 구현은 20바이트 **미만**만 "없음"으로 봐서 이 경우 정상 DB를 거절했다. 1절의 "비우기를 sync로 먼저 굳힌다" 덕분에 20바이트 이하 WAL에는 레코드가 있을 수 없으므로, 머리말만 새로 쓰면 잃는 것이 없다.
  - 그래서 비우기와 머리말 쓰기 사이의 sync(변이 C3)는 빼면 안 된다. SimFs에서는 20바이트 쓰기가 한 섹터 안이라 통째로 닿거나 안 닿아서, C3를 빼도 테스트가 잡지 못한다.
- **"s 없음, h = 0"**: 회차 0의 WAL은 DB를 만든 뒤 모든 커밋을 담고 있다. 그래서 첫 정리 도중 정전으로 장부가 반쯤 쓰였어도 장부를 볼 필요가 없다.
- **표지가 깨졌는데 열리는 경우**: 정리 도중 정전(① ②)이거나, 최신이 아닌 쪽 표지가 깨진 경우다. 최신 표지가 정리가 끝난 **뒤에** 깨지면 다른 표지는 옛 회차라서 거절한다(결정 3). 조용히 틀린 데이터로 여는 것보다 낫다.

## 4. 커밋과 닫기

- 커밋은 지금과 같다(WAL에 쓰고 sync 한 번). 그 뒤 WAL이 `CHECKPOINT_AFTER`(4MiB)보다 길면 정리한다. 정리가 실패하면 커밋은 이미 디스크에 있지만 `Err`를 돌려준다. `commit`의 문서는 원래 "`Io` 오류면 결과를 알 수 없다"라고 약속하므로 그 범위 안이다.
- 재시작 시간: WAL은 `CHECKPOINT_AFTER` + 커밋 하나를 넘지 않는다. 10MB 값 같은 **커밋 하나가 그보다 크면** 그만큼 길어질 수 있다.
- 바뀐 페이지 목록: `Wal`이 "마지막 정리 뒤 WAL에 들어간 페이지 번호"를 들고 있다. 정리는 그 페이지들을 **메모리의 트리에서** 꺼내 쓴다. 트리가 최신 커밋이라 WAL의 마지막 사본과 같다. WAL을 다시 읽지 않는다.
- 정리할 것이 없으면(WAL에 커밋이 없으면) 아무것도 쓰지 않는다.

## 5. 바뀐 공개 API

| 더한 것 | 왜 |
|---|---|
| `Db::checkpoint()` | 테스트와 도구가 정리를 직접 부르도록 |
| `CHECKPOINT_AFTER` | WAL이 이만큼 길어지면 정리한다. 재시작 시간 테스트가 쓴다 |
| `Db::close()` | 이제 정리를 한다. 실패하면 `Err` |

`Db::page_count()`의 계약: 정리 뒤 데이터 파일 길이 = `page_count() × 4096`. 테스트로 확인한다.

### 디스크에서 읽은 숫자로 하는 계산 (S3 연쇄 점검)

| 자리 | 계산 | 넘칠 수 있었나 | 처리 |
|---|---|---|---|
