# 0017. SQL 첫 관통: 렉서·파서·실행기 — 설계

이슈 #31. 지금까지 Oakdb는 "바이트 키에 바이트 값"만 아는 키-값 엔진이었다. 이번 티켓에서 처음으로 **SQL 문자열**을 받아 실행하는 입구가 생긴다. 렉서가 문장을 낱말로 자르고, 파서가 낱말을 구조(문장 나무)로 바꾸고, 실행기가 그 구조를 엔진의 `get`/`put` 호출로 옮긴다. 범위는 `CREATE TABLE`, `INSERT`, 기본 키 하나로 찾는 `SELECT`까지다. 범위 검색(#32), WHERE 필터(#33), 오류 다듬기(#34), BEGIN/COMMIT(#35)은 뒤 티켓이다.

**비유**: 엔진은 **번호표만 보고 물건을 넣고 꺼내는 창고**다. 창고 직원은 "3번 칸에 이 상자"만 알아듣는다. SQL 층은 그 앞의 **접수 창구**다. 손님이 "사용자 표에 김씨를 넣어 주세요"라고 말하면 창구 직원이 ① 말을 낱말로 끊어 듣고(렉서), ② 문장 구조를 파악하고(파서), ③ "사용자 표의 1번 칸 = 김씨 상자"라는 번호표로 바꿔 창고에 넘긴다(실행기). 중요한 것은 **번호표를 매기는 규칙**이다. 창고는 번호표를 사전 순서로 정렬해 둔다. 그래서 번호 1, 2, 10이 바이트로도 1 < 2 < 10 순서가 되게 매겨야 나중에 "1번부터 10번까지"(#32)를 한 번의 훑기로 꺼낼 수 있다. 문자 "10"과 "2"를 그대로 쓰면 사전 순서로는 "10"이 "2"보다 앞이라 틀린다.

```
"INSERT INTO users VALUES (1, 'kim')"
  렉서  → [INSERT] [INTO] [users] [VALUES] [(] [1] [,] ['kim'] [)]
  파서  → Insert { table: users, rows: [[1, 'kim']] }
  실행기 → 표 정보 읽기: users = 표 번호 1, 열 (id INTEGER PK, name TEXT)
         → put( 01 | 00 00 00 01 | 80 00 00 00 00 00 00 01 ,  01 ..1 | 02 00 00 00 03 6b 69 6d )
                 행   표 번호 1     기본 키 1 (부호 비트 뒤집음)       INTEGER 1   TEXT "kim"
```

## 1. 키 배치

엔진의 키 공간 하나를 첫 바이트로 나눠 쓴다.

| 첫 바이트 | 뒤에 오는 것 | 값 | 예 |
|---|---|---|---|
| `00` (그 뒤 없음) | — | 다음에 줄 표 번호 (u32 빅엔디언) | `00` → `00 00 00 02` |
| `00` | 표 이름 UTF-8 | 표 정보 (2-3절) | `00 75 73 65 72 73` ("users") |
| `01` | 표 번호 u32 BE + 기본 키 | 행 (2-2절) | `01 00 00 00 01 80 00 00 00 00 00 00 01` |

- **카운터를 `[0x00]` 하나에 두는 이유**: 표 이름은 빈 문자열일 수 없다(식별자는 한 글자 이상). 그래서 `[0x00]` 단독 키는 어떤 표 정보와도 겹치지 않고, 카탈로그 범위 안에서 맨 앞에 정렬된다. 키가 없으면(처음) 표 번호 1부터 준다.
- **표 이름이 아니라 번호로 행을 묶는 이유**: 키가 짧아지고(이름 길이와 무관하게 4바이트), 나중에 표 이름을 바꾸는 기능이 생겨도(이번 범위 밖) 행을 옮길 필요가 없다.
- **빅엔디언인 이유**: 표 1의 행이 모두 표 2의 행보다 앞에 모인다. 한 표의 행이 키 공간에서 한 덩어리라 "표 전체 훑기"가 범위 하나다.

## 2. 인코딩 (바이트 예)

### 2-1. 기본 키: 순서를 지키는 인코딩 (C4)

**INTEGER**: i64를 빅엔디언 8바이트로 쓰고 맨 앞 비트(부호 비트)를 뒤집는다. 2의 보수에서는 음수의 맨 앞 비트가 1이라 그대로 두면 음수가 양수보다 뒤에 온다. 뒤집으면 음수는 `0…`, 양수는 `1…`로 시작해 순서가 맞는다.

| 값 | 2의 보수 (BE) | 부호 비트 뒤집은 키 |
|---|---|---|
| i64::MIN | `80 00 00 00 00 00 00 00` | `00 00 00 00 00 00 00 00` |
| -1 | `FF FF FF FF FF FF FF FF` | `7F FF FF FF FF FF FF FF` |
| 0 | `00 00 00 00 00 00 00 00` | `80 00 00 00 00 00 00 00` |
| 1 | `00 00 00 00 00 00 00 01` | `80 00 00 00 00 00 00 01` |
| i64::MAX | `7F FF FF FF FF FF FF FF` | `FF FF FF FF FF FF FF FF` |

**TEXT / BLOB**: 바이트를 그대로 쓰되 `00`은 `00 FF`로 바꾸고, 끝에 `00 00`을 붙인다.

| 값 | 키 |
|---|---|
| `"a"` | `61 00 00` |
| `"a\0"` | `61 00 FF 00 00` |
| `"ab"` | `61 62 00 00` |

`"a" < "a\0" < "ab"`이고, 키도 `61 00 00 < 61 00 FF … < 61 62 …`다. 끝 표시 `00 00`은 "여기서 끝"이 어떤 내용 바이트보다도 작게 정렬되게 하고, 내용 속의 `00`은 `00 FF`라서 끝 표시와 헷갈리지 않는다. 지금은 기본 키가 키의 맨 끝이라 끝 표시 없이도 순서는 맞지만, 나중에 키 뒤에 무언가 붙는 경우(보조 인덱스 등)에도 순서가 깨지지 않게 처음부터 넣는다.

**표 하나 안에서 기본 키의 종류는 하나**라 키에 종류 바이트를 넣지 않는다.

### 2-2. 행 값 (C6)

열 순서대로(기본 키 열 포함) 종류 바이트 + 내용을 이어 붙인다. 길이는 u32 빅엔디언.

| 종류 바이트 | 종류 | 내용 |
|---|---|---|
| `00` | NULL | 없음 |
| `01` | INTEGER | i64 8바이트 BE (2의 보수 그대로, 순서가 필요 없어서) |
| `02` | TEXT | 길이 4바이트 + UTF-8 |
| `03` | BLOB | 길이 4바이트 + 바이트 |

예: `CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, photo BLOB)`에 `(1, 'kim', NULL)`

```
01 00 00 00 00 00 00 00 01   id = 1
02 00 00 00 03 6b 69 6d      name = 'kim'
00                           photo = NULL
```

기본 키를 값에도 넣는 이유: 행 값만 보고 행 전체를 되살릴 수 있어 실행기가 단순하다. 몇 바이트 중복되는 비용은 받아들인다.

### 2-3. 표 정보 (카탈로그 값)

```
표 번호 u32 BE | 열 개수 u16 BE | 기본 키 열 위치 u16 BE | 열마다: 이름 길이 u16 BE, 이름 UTF-8, 종류 바이트(01/02/03)
```

예: `users` (표 번호 1)

```
00 00 00 01  00 03  00 00
00 02 69 64 01            id    INTEGER
00 04 6e 61 6d 65 02      name  TEXT
00 05 70 68 6f 74 6f 03   photo BLOB
```

## 3. 문법 (C7)

```
문장      := (create | insert | select) [";"]
create    := CREATE TABLE 이름 "(" 열정의 ("," 열정의)* ")"
열정의    := 이름 종류 [PRIMARY KEY]
종류      := INTEGER | TEXT | BLOB
insert    := INSERT INTO 이름 ["(" 이름 ("," 이름)* ")"] VALUES 행 ("," 행)*
행        := "(" 리터럴 ("," 리터럴)* ")"
select    := SELECT ("*" | 이름 ("," 이름)*) FROM 이름 WHERE 이름 "=" 리터럴
리터럴    := ["-"] 정수 | '글자' | X'16진수' | NULL
이름      := [A-Za-z_][A-Za-z0-9_]*  (키워드는 이름으로 못 씀)
```

**렉서**는 낱말(단어, 정수, 글자, BLOB, 기호)과 각 낱말의 시작 위치(바이트, 0부터)를 낸다. `'it''s'`는 `it's`, `X'ab01'`은 바이트 `ab 01`이다. 홀수 자릿수나 16진수가 아닌 글자, 닫히지 않은 따옴표는 문법 오류다. `<`, `>`, `.`, `+` 같은 기호도 낱말로 자른다. 그래야 파서가 "`>`는 지원 안 함"이라고 말할 수 있다.

**파서**는 문법 하나에 함수 하나인 재귀 하강이다.

| 만난 것 | 오류 |
|---|---|
| 진짜 SQL에는 있지만 이번 범위가 아닌 것: `UPDATE`, `CREATE INDEX`, `REAL` 종류, `NOT NULL`, `WHERE id > 1`, WHERE 없는 SELECT, `ORDER BY`, 두 번째 문장 | **지원 안 함**: 무엇을 만났는지 이름을 댐 |
| 구조가 깨진 것: 닫는 괄호 없음, 쉼표 자리에 이상한 것, 끝나지 않은 따옴표 | **문법 오류**: 위치와 기대한 것 |

기본 키가 없거나 둘 이상인 표, 기본 키가 아닌 열로 찾는 WHERE도 "지원 안 함"이다(복합 키와 필터는 범위 밖, #33).

## 4. 오류 (C8)

`SqlError` 열거형. `#[non_exhaustive]`라 #34가 종류를 더해도 쓰는 쪽이 깨지지 않는다.

| 종류 | 언제 |
|---|---|
| `Syntax { position, message }` | 렉서·파서가 구조를 못 읽음. `position`은 문장 안의 바이트 위치(0부터) |
| `Unsupported(String)` | 이번 범위 밖의 SQL. 만난 것을 문장으로 담음 |
| `NoSuchTable(String)` | 없는 표 |
| `NoSuchColumn { table, column }` | 표에 없는 열 |
| `TableExists(String)` | 같은 이름의 표가 이미 있음 |
| `DuplicateColumn(String)` | CREATE나 INSERT 열 목록에 같은 열이 두 번 (6절) |
| `ValueCount { expected, found }` | INSERT 행의 값 개수가 열 개수와 다름 (6절) |
| `DuplicateKey { table }` | 같은 기본 키의 행이 이미 있음(같은 INSERT 안에서 둘인 경우도) |
| `TypeMismatch { column, expected, found }` | 값의 종류가 열 종류와 다르고 NULL도 아님, 또는 기본 키가 NULL |
| `Corrupt(String)` | 엔진에 저장된 표 정보·행을 읽을 수 없음 (6절) |
| `Engine(oakdb::Error)` | 엔진이 낸 오류 그대로 (키가 너무 김, 디스크 실패 등) |

오류가 나면 그 문장의 트랜잭션은 **커밋하지 않고 버린다.** 그래서 행 세 개짜리 INSERT의 세 번째 행이 기본 키 중복이면 앞의 두 행도 들어가지 않는다.

## 5. API (C9)

```rust
pub fn execute<F: Fs>(db: &Db<F>, sql: &str) -> Result<Output, SqlError>;

pub enum Output {
    Rows { columns: Vec<String>, rows: Vec<Vec<Value>> },  // SELECT
    Affected(u64),                                          // INSERT: 넣은 행 수
    Done,                                                   // CREATE TABLE
}

pub enum Value { Null, Integer(i64), Text(String), Blob(Vec<u8>) }
```

문장마다 `db.begin()` → 일 → `commit()`. SELECT도 같은 길로 간다(쓰기가 없으면 커밋은 아무것도 안 쓴다). 표 정보는 매 문장 엔진에서 읽는다. 캐시를 두면 빠르지만, 트랜잭션(#35)과 함께 무효화 규칙을 정해야 해서 미룬다.

## 6. C1~C9 밖에서 정한 것

| 무엇 | 정한 것 | 이유 |
|---|---|---|
| 카운터 키 | `[0x00]` 단독, 값은 다음 번호 u32 BE, 없으면 1 | 빈 표 이름이 없어서 안 겹침 (1절) |
| 이름의 대소문자 | 표·열 이름은 **쓴 그대로 구별**(`Users`와 `users`는 다름). 키워드만 대소문자 무시 | 단순하고 예측 가능. SQL 표준식 접기는 필요하면 #34에서 |
| 키워드를 이름으로 | 못 씀 (`CREATE TABLE select (...)`는 문법 오류) | 따옴표 이름(`"select"`)은 범위 밖 |
| INSERT 열 목록에 빠진 열 | NULL. 기본 키 열이 빠지면 기본 키 NULL → 타입 불일치 | C5와 C8 그대로 |
| WHERE 값의 종류 | 기본 키 종류와 다르면 타입 불일치. `WHERE id = NULL`은 행 없음 | SQL에서 `= NULL`은 참이 될 수 없다 |
| 정수 범위 | i64 밖이면 문법 오류(위치 포함). `-9223372036854775808`은 됨 | 렉서는 부호 없는 숫자만 자르고 파서가 `-`와 합친다 |
| 오류 종류 셋 더함 | `DuplicateColumn`, `ValueCount`, `Corrupt` | 기존 종류에 억지로 넣으면 메시지가 틀려진다. `Corrupt`는 패닉 대신 |
| 위치 | 바이트 위치, 0부터 | 렉서가 이미 바이트로 걷는다. 사람용 줄·칸 표시는 #34 |
| SELECT 결과의 행 | 찾으면 1행, 없으면 0행 | 기본 키 같음 비교라 최대 1행 |
| 동시에 실행한 CREATE TABLE (PR #62 리뷰 W1, 사용자 결정) | 이름이 달라도 둘 다 카운터 키 `[0x00]`을 쓰므로 #26(충돌 판정) 뒤에는 **나중 쪽이 `Engine(Conflict)`로 실패**한다. 표 번호는 겹치지 않는다. 받아들인다 | DDL은 드물다. **#26 전에는** 둘이 같은 번호를 받을 수 있으므로 #26(PR #63)을 먼저 머지한다. 동시 CREATE 테스트는 그 뒤에 더한다 |
| 값 길이 (리뷰 V3) | 글자·바이트 하나가 4바이트 길이 칸(`u32::MAX`)을 넘으면 행을 인코딩할 때 `Engine(ValueTooLarge)`. 행 전체 크기는 엔진이 막는다 | 길이 칸이 있는 곳에서 검사해 패닉이 없다 |
| 오류 종류 셋과 대소문자 구별 (리뷰 W4) | 위 표대로 | 사용자 결정 (추천안) |

## 7. 테스트 계획

이슈의 완료 기준대로 **SQL 문자열을 실행한 결과만** 본다(엔진 키를 직접 들여다보지 않는다). 예외는 인코딩 순서 속성 테스트와 렉서 단위 테스트다.

| 테스트 | 무엇을 |
|---|---|
| `encoding.rs` 속성 테스트 (proptest) | 무작위 i64 쌍, 무작위 바이트열 쌍(0x00·0xFF가 자주 나오게)마다 `인코딩 a`와 `인코딩 b`의 바이트 비교 = `a`와 `b`의 값 비교. 행 값·표 정보는 인코딩 → 디코딩 왕복 |
| `lexer.rs` 단위 테스트 | 키워드 대소문자, `''`, `X'..'`, 음수, 위치, 닫히지 않은 따옴표·잘못된 16진수 |
| `tests/sql.rs` | CREATE → INSERT → SELECT 왕복, 열 고르기, 열 목록 INSERT, 여러 행, NULL, `''`와 BLOB, i64 끝값, 엔진을 닫고 다시 열어도 표·행이 남음 |
| `tests/sql.rs` 오류 | 오류 종류마다 하나 이상: 지원 안 함(UPDATE, `>`, WHERE 없음, REAL, 두 문장), 문법 오류 위치, 없는 표·열, 이미 있는 표, 기본 키 중복과 그때 같은 문장의 앞 행도 안 들어감, 타입 불일치, NULL 기본 키 |
| `tests/sql.rs` 정전 | `SimFs`에서 INSERT를 응답받은 뒤 `crash(seed)` → 다시 열기, 시드 여러 개 → 표 정보와 응답한 행이 모두 SELECT로 보임. 행 세 개짜리 INSERT의 **모든 디스크 연산**에서 정전 → 세 행이 다 있거나 다 없음, 응답했으면 다 있음 |
| `tests/sql.rs` 실제 파일시스템 | 임시 디렉터리에서 `Db::open`으로 한 번 왕복 |
