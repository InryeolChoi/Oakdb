# 0010. WAL 쓰기와 재생 — 설계

이슈 #22, ADR 0007. 09번 정전 실험에서 지금 설계는 시드 1만 개 중 49%가 깨졌다. 이번 티켓은 그 표를 "약속 지킴 100%"로 바꾸는 것이 목표다. 결과는 `docs/experiments/0009-power-cuts-with-the-wal.md`에 있다.

**비유**: 지금까지는 장부(데이터 파일)를 연필로 바로 고쳐 썼다. 고치다 정전이 나면 장부가 찢긴다. 이제는 장부 옆에 **일지(WAL)**를 둔다. 고친 페이지를 통째로 일지 끝에 붙이고, 마지막 줄에 "여기까지 커밋" 도장을 찍은 뒤에야 OK를 준다. 다시 열 때는 도장까지 찍힌 내용만 일지에서 옮긴다. 도장 없이 끝난 꼬리는 버린다.

## 사용자가 정한 것

| # | 질문 | 결정 |
|---|---|---|
| 1 | 체크포인트(#23) 전까지 커밋이 데이터 파일에도 쓰나 | **WAL에만 쓴다.** 데이터 파일은 #23의 체크포인트만 쓴다. 다시 열면 WAL 전체를 다시 옮긴다. 대가: #23 전까지 WAL이 계속 커지고, 여는 시간이 그만큼 늘어난다 |
| 2 | 새 DB 만들기 | **WAL의 첫 커밋으로 만든다.** 데이터 파일은 빈 채로 남는다. 규칙: "데이터 파일이 비었고 WAL에 도장 찍힌 커밋이 없으면 새 DB". 만들기는 OK를 준 적이 없으니, 만드는 도중의 정전은 잃는 것 없이 새로 만들면 된다 (실험 0008의 시드 184·536) |
| 3 | 레코드 체크섬과 꼬리 처리 | **사슬 체크섬 + 끝 자르기.** 레코드마다 CRC-32C를 두되 앞 레코드의 CRC에서 이어 계산한다(SQLite 방식). 열 때 마지막 커밋 뒤를 잘라 내고 sync한다 |

## 1. WAL 파일 형식 (`oakdb.wal`)

머리말 없이 레코드가 이어진다. 정수는 little-endian이다.

| 레코드 | 내용 | 크기 |
|---|---|---|
| 페이지 | 종류 1 (u8) · 페이지 번호 (u64) · 페이지 4096바이트 · crc (u32) | 4,109바이트 |
| 커밋 | 종류 2 (u8) · root · page_count · free_head (0 = 없음) · free_count (u64 넷) · crc (u32) | 37바이트 |

- **crc** = `crc32c_append(앞 레코드의 crc, 이 레코드의 crc 앞 바이트 전부)`. 즉 앞 레코드의 CRC-32C 계산을 끊지 않고 이 레코드까지 이어 간 값이다. 첫 레코드는 고정값 `START` = `0x0AC0_DB10`에서 시작한다. 0이 아니라서 0으로 찬 파일은 통과하지 못한다.
- **페이지 이미지**는 데이터 파일에 쓸 때와 똑같이 페이지 체크섬(07번)까지 채운 상태로 넣는다. 체크포인트(#23)는 이 바이트를 그대로 데이터 파일에 옮기면 된다.
- **커밋 레코드**에 메타 필드를 넣는다. 그래서 커밋 레코드가 곧 "새 메타 페이지"이고, 데이터 파일의 메타 슬롯은 체크포인트 때만 바뀐다.

### 왜 사슬인가

레코드마다 따로 CRC를 두면, 어떤 레코드가 **제자리가 아닌 곳에서도** 통과한다. 예: 정전으로 커밋 B의 페이지 레코드는 온전히 남았는데 도장이 없다. 다시 열어 꼬리를 자르지 않고 커밋 C를 그 자리에 덮어쓰는 도중 또 정전이 나면, C의 앞부분 뒤에 B의 옛 레코드가 온전한 채로 이어질 수 있다. 사슬이면 B의 옛 레코드는 B의 앞 레코드에서 이어 계산한 값이라 C 뒤에서는 맞지 않는다. #23에서 WAL을 비우고 다시 쓸 때도 같은 이유로 옛 레코드가 끼어들지 못한다.

## 2. 커밋

1. 트리 복사본을 고친다 (지금과 같음).
2. 바뀐 페이지마다 페이지 레코드, 마지막에 커밋 레코드를 **버퍼 하나에** 만든다.
3. WAL 끝(`end`)에 한 번에 쓰고 **sync 한 번**. 그다음에야 `end`와 `crc`를 앞으로 옮기고 새 트리를 바꿔 끼운다.

지금까지는 sync가 한두 번이었다(페이지 sync, 페이지가 늘면 메타 sync). 이제는 언제나 한 번이다.

- **바꾼 것이 없는 커밋은 아무것도 쓰지 않는다.** 없는 키만 지우는 커밋이 그렇다. 페이지가 하나도 안 바뀌고 메타도 같으면 WAL에 쓰지 않는다(리뷰 뒤).
- **실패**: 쓰기나 sync가 실패하면 끝 위치가 그대로라서 다음 커밋이 그 자리를 덮어쓴다. ADR 0007은 "재시도하지 않고 엔진 정지"라고 정했지만, 그 일은 #24다. **#24 전까지는 이 덮어쓰기가 사실상 재시도다**(fsync가 한 번 실패한 파일을 다시 믿는 셈). 알려진 구멍으로 남긴다.

## 3. 열기

```text
데이터 파일 열기·잠금 → WAL 열기 → WAL 재생
→ 검사 (아무것도 바꾸지 않음)
    데이터 파일이 비어 있지 않으면: WAL 메타가 있으면 머리말만, 없으면 메타 페이지까지 검사
    메타 = WAL의 마지막 커밋 메타, 없으면 데이터 파일의 메타
    → 있음: 페이지마다 WAL에서, 없으면 데이터 파일에서 읽어 트리 검사
    → 없음, WAL이 새 DB의 첫 커밋(4,146바이트)보다 김: 거절 (Corrupt)
    → 없음, 그보다 짧음: 새 DB
→ 마지막 커밋 뒤에 바이트가 있으면: oakdb.wal.cut 끝에 덧붙여 sync, 디렉터리 sync,
   그다음 WAL을 잘라 내고 sync
→ 새 DB면 빈 트리를 첫 커밋으로
→ WAL에 커밋이 없었으면 디렉터리 sync (방금 만든 WAL 파일이 남도록)
```

**검사를 먼저, 바꾸기는 나중에** (리뷰 뒤). 처음 구현은 데이터 파일을 검사하기 전에 WAL을 잘랐다. 그러면 거절되는 DB도 WAL은 이미 잘려 있다.

- **재생**: 앞에서부터 읽으며 페이지 레코드는 "대기"에 모으고, 커밋 레코드를 만나면 대기한 페이지를 적용하고 메타를 바꾼다. 종류를 모르거나, 길이가 모자라거나, crc가 다르면 그 자리에서 멈춘다. 도장 없는 페이지는 적용하지 않는다.
- **끝 자르기를 하는 이유**: 꼬리를 남긴 채 다음 커밋을 그 **뒤에** 붙이면, 다음에 열 때 재생이 꼬리에서 멈춰서 새 커밋을 못 본다. 응답한 커밋이 사라진다.
- **잘라 낸 바이트는 버리지 않는다** (리뷰 뒤). 정전이 남긴 꼬리라면 쓰레기지만, WAL **중간**의 레코드가 (정전이 아닌 이유로) 깨졌다면 그 뒤에는 응답한 커밋이 있다. 재생은 사슬 때문에 깨진 곳을 건너뛸 수 없다. 그래서 잘라 낸 바이트를 `oakdb.wal.cut`에 덧붙여 두고 자른다. 엔진이 되살리지는 않지만 영영 사라지지도 않는다.
- **커밋 없는 긴 WAL은 거절한다** (리뷰 뒤). 만드는 도중 정전은 첫 커밋(4,146바이트) 이하만 남긴다. 그보다 긴데 커밋이 하나도 없다면 첫 레코드가 깨진 것이다. 처음 구현은 이것을 "새 DB"로 보고 WAL을 0바이트로 잘랐다. 응답한 커밋 전부가 오류 없이 사라지는 경우였다.
- **페이지 검사**: WAL의 페이지 이미지도 페이지 체크섬으로 한 번 더 확인한다. 이미 레코드 crc가 지키지만, 데이터 파일에서 읽을 때와 같은 길을 지나게 했다.
- 트리 전체가 메모리에 있으므로(04번), WAL은 **열 때 한 번만** 읽는다. 커밋 중에 WAL에서 페이지를 찾아 읽는 일은 없다.

## 4. 바뀐 공개 API

| 더한 것 | 왜 |
|---|---|
| `WAL_FILE` (`"oakdb.wal"`) | 테스트와 도구가 WAL 파일을 찾도록 |
| `Db::page_count()` | DB가 쓰는 페이지 수(빈 페이지와 메타 두 장 포함). 체크포인트한 데이터 파일이 가질 페이지 수다. 지금까지 테스트는 데이터 파일 크기로 셌는데, 데이터 파일이 #23까지 비어 있어서 엔진에 물어보도록 바꿨다. 계약은 #23에서 다시 본다 |

## 7. 이번에 하지 않은 것

- **체크포인트와 WAL 비우기** (#23). 그 전까지 WAL은 계속 커진다.
- **지운 값 지우기.** 06번은 빈 페이지를 0으로 채워 지운 값이 데이터 파일에 남지 않게 했다. 하지만 WAL에는 옛 페이지 이미지가 #23이 WAL을 비울 때까지 남는다.
- **sync 실패 뒤 엔진 정지** (#24).
- **그룹 커밋** (#28). 지금은 커밋마다 sync 한 번.
- **WAL 머리말**(형식 버전, salt). #23에서 WAL을 다시 쓰기 시작할 때 필요하면 더한다. 파일 형식 기록은 #43.
