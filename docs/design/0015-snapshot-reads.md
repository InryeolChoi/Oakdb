# 0015. 스냅샷 읽기 — 설계

이슈 #25. 트랜잭션은 **시작한 순간에 커밋돼 있던 데이터베이스**를 읽는다. 그 뒤에 다른 트랜잭션이 커밋해도 보이지 않는다. 자기가 쓴 것만 그 위에 겹쳐 보인다. ADR 0006의 "실행은 동시에, 커밋만 한 줄로"에서 앞 절반이다. 뒤 절반인 충돌 판정은 #26(설계 0016)이다.

**비유**: 트랜잭션은 시작할 때 장부를 **사진으로 찍는다.** 일하는 동안은 사진만 본다. 남이 장부를 고쳐도 사진은 그대로다. 내가 고칠 것은 사진 위에 붙인 포스트잇에 적고, 커밋할 때 장부에 옮긴다.

## 정한 것

| # | 질문 | 결정 | 상태 |
|---|---|---|---|
| A1 | 스냅샷을 어떻게 만드나 | **`begin`이 메모리 속 트리(`Arc<Tree>`)를 한 번 잡아 둔다.** 키마다 버전을 붙이지 않는다 | 사용자 결정 (추천안) |
| A2 | 롤백 API | `txn.rollback()`. 이미 있었다(#17). 버리기(drop)와 같다 | 사용자 결정 (추천안) |

## 1. 왜 트리를 잡아 두는 것만으로 스냅샷이 되나

| 성질 | 어디서 | 그래서 |
|---|---|---|
| 파일 전체가 메모리에 있다 | `tree.rs` 머리 주석 | 스냅샷이 디스크를 다시 읽을 일이 없다 |
| 커밋은 트리를 복제해 고친 뒤 통째로 바꿔 끼운다 | ADR 0006 구현 메모(#17) | 잡아 둔 트리는 아무도 고치지 않는다 |
| 페이지는 `Arc`로 나눠 쓴다 | `Tree::pages: Vec<Arc<Page>>` | 복제는 바뀐 페이지만 복사한다. 스냅샷은 옛 페이지를 붙잡을 뿐이다 |
| 정리(체크포인트)는 데이터 파일을 쓰지 메모리 페이지를 쓰지 않는다 | `checkpoint.rs` | 정리가 디스크 페이지를 제자리에 덮어써도 스냅샷은 그대로다 |

그래서 바뀐 코드는 세 곳이다. `begin`이 트리를 잡고, `get`과 `scan`이 최신 트리 대신 그 트리를 읽는다. 이 구조는 ADR 0006 구현 메모가 #17 때 미리 적어 둔 길이다.

## 2. 버리지 않은 선택지: 키마다 버전

| | 트리를 잡아 둠 (택함) | 키마다 커밋 버전을 붙이고 옛 버전을 트리에 남김 |
|---|---|---|
| 코드 | `begin` 한 줄, `get`·`scan`이 읽는 트리만 바꿈 | 키 형식, 조회, 옛 버전 청소(GC)까지 새로 |
| 디스크 | 그대로 | 옛 버전이 디스크까지 감 |
| 대가 | 오래 사는 트랜잭션이 옛 페이지를 메모리에 붙잡음 | 청소가 밀리면 트리가 커짐 |
| 언제 필요해지나 | 트리를 메모리에 다 못 올릴 때 | — |

이슈 본문은 "키에 커밋 버전이 붙는다"였다. 트리를 통째로 메모리에 두는 동안은 그럴 필요가 없다. 페이지 캐시(일부만 메모리)로 바꾸는 날 다시 본다.

## 3. 바뀌는 동작

| 경우 | 전 (#17까지) | 지금 |
|---|---|---|
| `begin` 뒤 다른 커밋, 그다음 `get` | 새 값 | **시작 때 값** |
| `begin` 뒤 다른 커밋, 그다음 `scan` | 새 값 (scan을 시작할 때 트리) | **시작 때 값** |
| 자기 쓰기 | 보임 | 보임 |
| 롤백·버리기 | 흔적 없음 | 흔적 없음 |
| 커밋 | 최신 트리에 자기 쓰기를 반영 | **그대로.** 남이 같은 키를 먼저 커밋했으면 지금은 덮어쓴다(잃어버린 갱신). #26이 충돌로 막는다 |
| `get`의 잠금 | 트리 `Mutex`를 잠깐 잡음 | **안 잡음.** 스냅샷은 트랜잭션의 것이다. `begin`이 한 번 잡는다 |
