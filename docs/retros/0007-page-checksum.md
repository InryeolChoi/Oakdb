# 0007. 페이지 체크섬 — 회고

이슈 #19. 설계는 `docs/design/0007-page-checksum.md`. 검증 결과는 PR #51 코멘트에 있다.

## 만든 것

- **모든 페이지에 지문**: 파일에 쓸 때 CRC-32C(페이지 4~4096바이트 ‖ 페이지 번호)를 맨 앞 4바이트에 채우고, 읽을 때 다시 계산해 다르면 `Corrupt: page N has a wrong checksum`을 낸다.
- **쓰기와 읽기 길목이 하나씩**: 모든 쓰기는 `write_page`, 모든 읽기는 `read_page`를 지난다. 계산은 `checksum.rs` 한 곳에 있다.
- **메타를 읽는 순서**: magic → 페이지 크기 → 버전 → 체크섬 → 나머지. 그래서 버전 2 파일은 버전으로 거절된다. 형식 버전 3.
- `crc32c` crate 추가. 테스트 121개 → 133개.

## 배운 것

**"전에도 잡혔다"와 "운으로 잡혔다"는 다르다.** 실험 0006을 main과 이 브랜치에서 똑같이 돌렸다. main도 반쯤 쓴 페이지와 엉뚱한 자리의 페이지는 거절했다. 하지만 이유를 보니 우연히 키 순서가 깨졌거나 우연히 범위 검사에 걸린 것이었다. 같은 손상이 구조와 상관없는 바이트에 났다면 그냥 지나갔을 것이다. 실제로 값 바이트 하나와 부록의 비트 하나는 main에서 **열리고 틀린 값을 돌려줬다.** 체크섬은 어느 바이트든 잡고, 오류에 페이지 번호까지 적는다. 같은 실험을 전과 후에 돌려 비교하니 "무엇이 나아졌는지"가 표 한 장으로 보였다.

**가설은 나눠서 판정해야 한다.** "커밋과 열기가 거의 안 느려진다"를 한 문장으로 세웠다. 처음 쓴 판정은 "엔진 시간으로는 기각, 실제 커밋으로는 채택"이었는데, 리뷰 두 개가 세 군데를 짚었다. (1) 열기에는 sync가 없어서 +12%가 그대로 사용자 시간이니 열기는 기각이다. (2) "실제 커밋 0.01%"는 잰 값이 아니라 나눗셈으로 낸 추정이다. (3) 커밋 두 줄은 5라운드 중 4번만 느렸으니(p ≈ 0.19) 판정할 수 없다. 숫자는 그대로인데, 그 숫자로 말할 수 있는 것은 처음 판정보다 좁았다. 가설을 부분마다 나눠 표로 판정하고, 잰 것과 계산한 것을 구분해 적기로 했다. Linux에서는 sync가 55µs라 같은 비용이 약 0.5%라는 점도 ADR 0003에 맞춰 함께 적었다.

**실패하는 테스트를 먼저 커밋하니 범위가 분명해졌다.** 06 회고에서 약속한 대로 테스트 8개를 먼저 커밋했다(a8023ef). 그 테스트를 쓰면서 "메타 B는 지금 읽지 않는다"는 것을 구현 전에 알아챘고, 테스트에서 B를 빼고 이유를 주석으로 남겼다. 구현을 먼저 했다면 B를 건너뛴 것이 의도인지 빠뜨린 것인지 나중에 구분하기 어려웠을 것이다.

**손상과 "다른 파일"의 경계는 순서가 정한다.** 체크섬보다 형식 자리(magic·페이지 크기·버전)를 먼저 보기 때문에, 그 자리가 망가지면 "Oakdb 파일이 아님"으로 보고된다. 리뷰 둘과 눈 가린 테스터가 모두 이 점을 짚었다. 페이지 크기를 모르면 체크섬 범위도 모르니 순서는 바꿀 수 없다. 형식 오류에 "손상으로 보임"을 덧붙이는 방법은 페이지 크기가 다른 정상 파일을 잘못 말할 수 있어서 택하지 않았다(결정 3). 어느 쪽이든 열기를 거부한다는 점은 같다.

**Rust 쪽에서 눈여겨본 점**

- `checksum::sealed`는 처음에 `&[u8]`을 받았다. 4096바이트가 아니면 `copy_from_slice`에서 panic하는데, 그 조건이 타입에 없었다. `&[u8; PAGE_SIZE]`로 바꾸자 길이가 맞는지를 컴파일러가 확인하고, 복사도 `*page` 한 번으로 끝난다. Java라면 `byte[]` 길이를 실행 중에 검사해야 할 약속을 Rust는 타입(배열 길이)으로 말할 수 있다.
- 메모리의 페이지는 여러 트리가 `Arc`로 나눠 갖고 있어서, 쓸 때 체크섬을 채우려면 사본이 필요하다. 4KB 배열을 스택에 만드는 것으로 충분했다. 스레드 스택(2MB 이상)에 비하면 작다.
- `Meta::decode`를 `check_header`와 `read_fields`로 나눴다. 운영 코드는 "형식 → 체크섬 → 내용" 순서로 둘을 따로 부르고, 둘을 합친 `decode`는 테스트에만 남겼다(`#[cfg(test)]`).
