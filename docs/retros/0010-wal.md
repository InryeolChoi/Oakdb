# 0010. WAL 쓰기와 재생 — 회고

이슈 #22. 설계는 `docs/design/0010-wal.md`, 실험은 `docs/experiments/0009-power-cuts-with-the-wal.md`. 검증 결과는 PR #54 코멘트에 있다.

## 만든 것

- **WAL(`oakdb.wal`)**: 커밋은 바뀐 페이지 사본(페이지 체크섬 포함)과 메타를 담은 커밋 레코드를 한 번에 붙이고 **sync 한 번** 뒤에 응답한다. 레코드 체크섬은 앞 레코드에서 이어지는 사슬이다.
- **열기**: 재생 → 모든 검사 → 마지막 커밋 뒤의 바이트를 `oakdb.wal.cut`에 보관하고 잘라 냄 → 트리 구성. 데이터 파일은 체크포인트(#23) 전까지 비어 있고, 새 DB는 WAL의 첫 커밋이다.
- 공개 API `WAL_FILE`, `Db::page_count()`. A/B 도구 `ab_versions.py`(엔진 두 버전 비교), 변이 검사 WAL 버그 11개.

## 배운 것

**11만 개 시드가 통과해도, 시험이 만들지 않는 고장은 남는다.** 정전 실험은 100%였고 블라인드 테스터도 29개 모두 통과했다. 그런데 Spec 리뷰가 "WAL **첫 레코드**에서 비트 하나만 깨져도 DB가 오류 없이 빈 새 DB가 된다"를 찾았다. 가짜 디스크는 정전만 흉내 낸다. 정전은 **끝의** 쓰기만 찢는다. 중간 레코드가 썩는 일(디스크 오류, 버그)은 한 번도 만들지 않으니, 그 경우의 코드 경로는 실험에 나오지 않는다. 숫자가 좋을수록 "이 숫자가 다루지 않는 고장은 무엇인가"를 따로 물어야 한다. 테스트는 고장 모델의 범위까지만 증명한다.

**파괴적인 일은 검사가 다 끝난 뒤에.** 처음 구현은 열자마자 WAL 꼬리를 잘랐고, 그다음에 데이터 파일을 검사했다. 데이터 파일이 거절돼도 WAL은 이미 잘려 있었다. "열기는 실패했는데 파일은 바뀌었다"는 최악의 조합이다. 이제 열기는 두 단계다. 먼저 모든 것을 읽고 검사만 하고, 통과한 뒤에야 바꾼다. 그리고 바꿀 때도 버리지 않고 `oakdb.wal.cut`에 옮긴다. 복구할 수 없는 일을 하는 코드는 그 일을 마지막에, 되돌릴 수 있는 방식으로 한다.

**커밋 시간은 바이트가 아니라 sync 횟수다.** WAL은 같은 페이지를 레코드 머리와 체크섬까지 붙여 더 많이 쓴다. 그래도 페이지가 늘어나는 커밋은 23% 빨라졌다. sync가 두 번에서 한 번이 됐기 때문이다. 덮어쓰기는 원래 한 번이라 차이가 없었다. 실험 0002의 결론이 다시 확인됐고, 다음 속도 개선(그룹 커밋 #28)도 같은 곳을 노린다.

**정전 시점이 줄어든 것도 설계의 효과다.** 같은 작업의 "끊길 수 있는 자리"가 228개에서 62개가 됐다. 커밋 하나가 쓰기 한 번 + sync 한 번이라서다. 상태가 바뀌는 자리가 적을수록 따져야 할 중간 상태도 적다.

**ADR과 코드가 다른 말을 하면 리뷰가 먼저 본다.** ADR 0007은 "기록 실패 시 엔진 정지", 코드는 "다음 커밋이 덮어씀". 둘 다 리뷰어가 짚었다. 일부러 #24로 미룬 것이지만 그 사실이 설계 문서 한 줄에만 있었다. 미룬 결정은 ADR에도 "구현 메모"로 남겼다. 06번 보장(지운 값이 디스크에 안 남음)의 퇴행도 마찬가지로, 미룬 것은 #23 이슈에 체크리스트로 옮겨야 잊히지 않는다.

**Rust 쪽에서 눈여겨본 점**

- **고정 길이 배열을 타입에 담기**: 재생 결과의 페이지를 `Box<[u8]>`에서 `Box<[u8; PAGE_SIZE]>`로 바꿨다. "길이가 4096"이 주석이 아니라 타입이 된다. `Box<[u8; N]>`은 필요할 때 `Box<[u8]>`로 비용 없이 바뀐다(unsized coercion).
- **빌려 쓰다가 넘겨주기**: 처음엔 `&Replayed`를 받아 페이지마다 `clone()`했다. `Replayed`를 구조 분해해서 `pages`를 값으로 넘기고 `remove`로 꺼내자 복제가 사라졌다. 소유권을 넘기면 복사가 필요 없다는 Rust의 기본기다.
- **커밋 경로의 복사 한 번 줄이기**: 페이지를 체크섬 채운 사본으로 만든 뒤 버퍼에 다시 복사하던 것을, 버퍼에 한 번 복사하고 그 자리에서 체크섬을 채우게 바꿨다(`checksum::seal(page_no, &mut [u8])`). 할당도 `Vec::with_capacity(commit_len(n))` 한 번이다.
- **함께 다니는 값은 타입으로**: `(end, crc)`가 재생 결과와 WAL 양쪽에서 늘 같이 다녀서 `Tail`로 묶었다. `Tail::EMPTY`라는 상수 하나가 "커밋 없는 WAL"이라는 뜻까지 말해 준다.
- **`#[expect(dead_code, reason = …)]`**: #23이 쓸 코드(메타 페이지 인코딩, 데이터 파일 핸들)를 지우지 않고 남겼다. `allow`와 달리 `expect`는 그 코드가 쓰이기 시작하면 경고를 내서, 표시를 지우라고 알려 준다.
- **panic 대신 오류**: `usize::try_from(len).expect(…)`는 32비트에서 큰 WAL을 만나면 panic이다. 손상된 입력은 언제나 `Error::Corrupt`로 돌려주는 기존 관례에 맞췄다.

## 다음 이슈로 넘기는 것

- **#23 (체크포인트)**: ignore한 테스트 10개, 지운 값이 WAL과 cut 파일에 남는 문제, `expect(dead_code)` 셋, `page_count()` 계약, WAL을 다시 쓸 때 머리말이 필요한지. 이슈에 체크리스트로 남겼다.
- **#24 (디스크 실패)**: sync 실패 뒤 다음 커밋이 같은 자리에 다시 쓰는 문제.
- **가짜 디스크에 "중간 손상" 고장 더하기**: 이번 구멍은 고장 모델 밖에서 나왔다. 정전 말고도 비트 썩음을 흉내 내는 모드가 있으면 다음 티켓들도 그 경로를 시험할 수 있다. 필요해지면 이슈로 만든다.
