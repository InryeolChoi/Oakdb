# 0004. 여러 층 트리와 정답 모델 비교 — 회고

이슈 #16. 설계는 `docs/design/0004-multi-level-tree.md`. 검증 결과는 PR #47 코멘트에 있다.

## 만든 것

- **내부 페이지 분할**: 넘친 내부 페이지를 바이트 기준으로 반씩 나누고, 가운데 키는 부모로 올린다. 루트가 넘치면 새 루트가 생겨 트리가 한 층 자란다. 03번의 `PageFull`이 사라졌다.
- **빈 리프 빼기**: delete로 빈 리프는 부모에서 빠지고, 앞 리프의 옆 포인터가 그 리프를 건너뛴다. 자식이 하나만 남은 루트는 그 자식에게 자리를 넘겨 트리가 한 층 낮아진다. 합치기나 빌려 오기는 하지 않는다.
- **`Page` 정리**: 리프 전용·내부 전용 메서드는 debug 빌드에서 종류를 검사한다. 페이지가 찼다는 신호는 crate 안에서만 쓰는 `Full`로 바꿨다.
- **정답 모델 테스트**: proptest로 무작위 put/delete/연속 delete/get/커밋/롤백/다시 열기를 `BTreeMap`과 비교한다. 자라는 쪽과 줄어드는 쪽을 따로 둔다.
- 테스트 81개(단위 43, 통합 38). 새로 넣은 것은 트리 단위 테스트 7개, 여러 층 통합 테스트 6개, 모델 테스트 3개다.

| 검증 | 결과 |
|---|---|
| CI macOS · Linux | 통과 |
| 일부러 심은 버그 5개 | 모델 테스트와 단위 테스트 모두 5/5 잡음 |
| 눈 가린 테스터 | 11 통과 / 0 실패 |
| 리뷰 | 규칙 위반 0, 버그 0, 판단 7 (작은 수정은 반영) |

## 배운 것

**테스트가 통과했다고 그 길을 지나갔다는 뜻은 아니다.** 모델 테스트는 처음 쓴 그대로 통과했다. 그런데 경로마다 몇 번 지나갔는지 세어 보니, 4층으로 자라기와 루트 낮아지기는 **0번**이었다. 트랜잭션의 약 1/3이 롤백이나 다시 열기로 버려져서 키가 쌓이지 않았다. 무작위 테스트는 "어떤 분포에서 뽑는가"가 곧 "무엇을 검사하는가"다. 연산 비율을 바꾸고 테스트를 둘로 나눈 뒤에야 두 경로를 각각 40번 넘게 지나갔다. 그다음 버그를 심어 보고 잡히는 것까지 확인했다. 통과(초록불) → 지나간 경로 세기 → 버그 심어 보기 순서가 이번 티켓에서 가장 쓸모 있었다.

**내 테스트의 가정도 틀릴 수 있다.** "가장 큰 항목 1000개면 4층"이라고 짐작하고 테스트를 썼는데 실제로는 5층이었다. 분할한 페이지는 반만 차기 때문이다. 오름차순이든 흩어진 순서든 결과는 같았다. 높이를 직접 세는 테스트를 넣었기에 바로 드러났다.

**내부 분할은 리프 분할과 닮았지만 한 군데가 다르다.** 리프는 구분 키를 오른쪽 첫 키로 **남기고**, 내부 페이지는 가운데 키를 **올린다**. 리프의 키에는 값이 붙어 있고, 내부 키는 길 안내일 뿐이기 때문이다. 리뷰에서 "균형 지점 찾기 반복문이 두 곳에 있다"는 지적이 나왔지만, 이 차이 때문에 합치지 않기로 했다(결정 2).

**합치기를 안 하면 "자식 하나짜리 내부 페이지"가 생긴다.** 빈 리프만 빼면, 루트가 아닌 내부 페이지가 셀 0개(자식 1개)로 남을 수 있다. 찾기에는 문제가 없지만, 03번 깊이 상한(64)의 근거였던 "내부 페이지는 자식이 적어도 둘"이 깨졌다. 근거를 "층이 하나 늘 때마다 페이지가 두 배 넘게 필요하고, 페이지는 재사용하지 않는다"로 바꿨다. 다만 페이지 재사용(free list)이 들어오면 이 근거도 다시 봐야 한다.

**Rust 쪽에서 눈여겨본 점**

- `Page::put`의 실패를 공개 `Error::PageFull`에서 crate 안의 빈 구조체 `Full`로 바꿨다. "페이지가 찼다"는 트리가 처리할 일이지 사용자에게 알릴 일이 아니다. 타입을 따로 두니 `Tree::put`이 `Result`를 돌려줄 이유도 사라졌다. 실패할 수 없는 함수의 시그니처에서 실패가 빠졌다. Java로 치면 checked exception을 throws에서 지운 셈이다.
- 분할이 위로 번지는 코드는 재귀 대신 `path`(내려온 길)를 거꾸로 도는 반복문으로 짰다. `self.page_mut(parent)`로 빌린 페이지를 다 쓴 뒤에 `self.push(...)`를 부르도록 순서를 맞추면, 빌림 검사기가 별도 처리 없이 통과시킨다.
- 테스트에서 `proptest`의 `prop_oneof!` 가중치를 상수 구조체(`GROWING`, `SHRINKING`)로 묶었다. 비율을 바꿔 가며 경로 횟수를 재는 일이 쉬워졌다.

## 다음 이슈로 넘기는 것

- **#22 (WAL)**: 내부 분할과 빈 리프 빼기도 한 커밋에 여러 장을 쓴다. 중간에 멈추면 다시 열 때 트리 검사가 열기를 거부한다. 실험 0004의 세 경우에 이 두 경우를 더한다.
- **페이지 재사용 (free list)**: 빠진 페이지는 파일에 남는다. 들어오면 `a_tree_that_shrank_does_not_reuse_or_lose_pages_in_the_file`와 `MAX_DEPTH`의 근거를 고친다.
- **ADR 0009 (#43)**: 셀이 0개인 내부 페이지를 허용한다는 점을 파일 형식에 적는다.
- **#17 (범위 조회)**: 빈 리프를 빼도 옆 포인터 사슬이 이어지도록 했으니, 범위 조회는 사슬만 따라가면 된다.
