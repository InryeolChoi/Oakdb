# 0017. SQL 첫 관통 — 회고

이슈 #31. 설계는 `docs/design/0017-sql-first-pass.md`. 결정 C1~C9는 추천안대로 정했다. 구현은 엔진 쪽 티켓(#25, #26)과 **동시에** 다른 작업 트리에서 진행했다. SQL 층은 엔진 API(`begin`/`get`/`put`/`commit`)만 쓰므로 서로 부딪히지 않았다.

## 만든 것

- **새 크레이트 `crates/oakdb-sql`**: 렉서, 재귀 하강 파서, 순서를 지키는 키 인코딩, 카탈로그(표 정보), 실행기.
- **입구** `oakdb_sql::execute(&db, "…")`: `CREATE TABLE`, 여러 행 `INSERT`, 기본 키 `SELECT`. 문장 하나가 엔진 트랜잭션 하나다.
- **키 배치**:
  - 행은 `[01][표 번호][기본 키]`, 표 정보는 `[00][이름]`, 다음 표 번호는 `[00]`에 둔다.
  - 기본 키는 바이트 순서가 값 순서와 같다. 정수는 부호 비트를 뒤집고, 글자·바이트는 `00`을 `00 FF`로 바꾸고 `00 00`으로 끝낸다.
- **테스트 63개**:
  - 단위 테스트 30개: 렉서, 인코딩 속성 테스트 각 5000쌍, 카탈로그.
  - SQL 문자열 테스트 32개: 정전 뒤 응답한 행이 남는지, 세 행 INSERT를 디스크 연산마다 끊어도 원자적인지 포함.

| 검증 | 결과 |
|---|---|
| 실패하는 테스트 먼저 | 9b7a6b6 (스텁, 실행하면 전부 실패). 이 커밋만 `-D warnings`로 빌드하면 쓰지 않는 코드 경고로 실패한다(리뷰 V1) |

| 리뷰 | 규칙: 위반 1(V1) · 판단 5 / 완료 조건: 5/6 충족(나머지는 이 회고), 중간 1(W1 동시 CREATE) · 낮음 5 |

## 배운 것

**층을 나누면 동시에 만들 수 있다.** SQL 크레이트는 엔진의 공개 API만 쓰고, 엔진은 SQL을 모른다(ADR 0005). 그래서 엔진의 트랜잭션 내부가 바뀌는 동안(#25 스냅샷, #26 충돌) SQL을 따로 만들 수 있었다. 둘이 만나는 지점은 "문장 하나 = 트랜잭션 하나"라는 약속 하나뿐이다.

**아래층의 규칙이 위층의 동작을 정한다.** 리뷰가 짚었다(W1). 표 번호 카운터를 키 하나(`[00]`)에 두었기 때문에, #26이 들어오면 **동시에 실행한 CREATE TABLE 두 개는 충돌한다.** 같은 키를 쓰니 나중 쪽이 진다. 덕분에 번호가 겹치지는 않는다. 대신 DDL이 한 줄로 선다. 같은 기본 키로 동시에 INSERT해도 "기본 키 중복"이 아니라 엔진의 충돌 오류가 난다(W2). SQL 층을 설계할 때는 아래 엔진의 격리 규칙까지 함께 봐야 한다.

**순서를 지키는 인코딩은 지금 쓰지 않아도 지금 정한다.** 이번 티켓의 SELECT는 기본 키 하나로만 찾아서 순서가 필요 없다. 하지만 #32(범위 조회)가 오면 "키 범위 = 기본 키 범위"가 그대로 쓰인다. 저장 형식은 바꾸기 어렵다. 그래서 순서는 지금 속성 테스트로 증명해 두었다. `"a" < "a\0" < "ab"`, `i64::MIN`과 음수가 모두 맞다.

**"지원 안 함"과 "문법 오류"의 경계는 생각보다 흐리다.** `CREATE TABLE IF NOT EXISTS`는 `IF`를 표 이름으로 읽어 문법 오류가 난다. `SELECT COUNT(*)`도 그렇다(리뷰 W3). 사용자에게는 둘 다 "안 된다"이지만, 무엇을 고쳐야 하는지는 다르다. #34(오류 종류)에서 다듬는다.

**Rust 쪽에서 눈여겨본 점**

- **오류를 열거형으로, `#[non_exhaustive]`로**: #34에서 종류가 늘어도 쓰는 쪽 코드가 깨지지 않는다.
- **믿을 수 없는 입력에 패닉 없이**: 눈 가린 테스터가 SQL 낱말 2000개를 무작위로 이어 넣었는데 한 번도 패닉하지 않았다. 다만 인코딩의 `unreachable!`/`expect` 몇 곳은 다른 모듈의 검사에 기댄다(리뷰 V2). 지금은 닿을 수 없지만 불변식이 모듈 경계를 넘는다.
- **엔진의 `Fs`에 제네릭**: `execute<F: Fs>`라서 가짜 디스크로 정전 테스트를 그대로 돌린다.

## 다음 이슈로 넘기는 것

- **#32 범위 조회**: SQL 수준의 순서 테스트를 그때 더한다.
- **#34 오류 종류**: 동시 INSERT의 충돌과 기본 키 중복 구분, 지원 안 함과 문법 오류의 경계, 너무 긴 키로 SELECT하는 경우.
- **동시 CREATE TABLE이 한 줄로 서는 것**: 지금은 안전하고 드물다. 필요해지면 표 번호를 다른 방식으로 매긴다.
