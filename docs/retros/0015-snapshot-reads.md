# 0015. 스냅샷 읽기 — 회고

이슈 #25. 설계는 `docs/design/0015-snapshot-reads.md`. 결정 두 개(A1 트리를 잡아 둠, A2 롤백 API)는 추천안대로 정했다. A2는 이미 있었다.

## 만든 것

- **`begin`이 트리를 잡는다**: `Txn`이 `snapshot: Arc<Tree>`를 들고, `get`과 `scan`이 그 트리를 읽는다. `get`은 더 이상 트리 잠금을 잡지 않는다.

## 배운 것

**설계가 미리 길을 깔아 두면 구현은 세 줄이다.** #17에서 "커밋은 복제한 트리를 바꿔 끼운다"를 고를 때 ADR 메모에 "스냅샷 티켓에서 `begin`이 `Arc`를 한 번 잡으면 된다"고 적어 두었다. 이번 변경은 정말 그것뿐이었다. 시간은 코드가 아니라 "정말 그것뿐인가"를 확인하는 데 들었다. 메모리 속 페이지가 제자리에서 바뀌는 길(`page_mut`, `take_dirty`, 체크포인트, 풀린 overflow 페이지의 재사용)을 하나씩 따라가 옛 `Arc`에서 닿는 페이지는 아무도 고치지 않는다는 것을 보였다. 리뷰도 같은 길을 따로 따라가 같은 결론을 냈다.

**이슈 본문과 다른 결정은 이슈에도 남겨야 한다.** 이슈는 "키에 커밋 버전이 붙는다"였고, 결정은 "트리를 잡아 둔다"였다. 설계 문서와 ADR 메모에는 적었지만 이슈만 읽는 사람은 모른다(리뷰 U2). 결정이 이슈 문구와 다르면 이슈에도 댓글을 단다.

**잠금 하나를 덜 잡으면 다른 데서 하나를 더 잡는다.** `get`은 잠금을 안 잡게 됐지만 `begin`이 잡는다. 커밋은 sync가 끝날 때까지 이 잠금을 쥐므로, 이제 **트랜잭션 시작**이 남의 커밋 sync를 기다린다(리뷰 T2). 한 스레드에서는 보이지 않는다. 여러 스레드(#27)와 그룹 커밋(#28)에서 커밋이 sync 동안 잠금을 놓도록 바꿀 때 함께 본다.

**Rust 쪽에서 눈여겨본 점**

- **`Arc`가 곧 스냅샷**: 스냅샷을 만드는 비용은 참조 카운트 하나다. 페이지가 `Arc<Page>`이고 고칠 때 `Arc::make_mut`로 복사하니, "옛 판을 아무도 고치지 않는다"를 타입이 지켜 준다. 공유된 페이지를 고치려면 반드시 복사가 일어난다.
- **잠금 가드의 수명**: `Arc::clone(&self.tree())`는 가드가 문장 끝에서 풀리는 임시값이라, `begin`이 잠금을 쥐는 시간은 복제 한 번뿐이다.
- **`Txn`은 `Send + Sync`**: `&Db`와 `Arc<Tree>`만 들어서 #27에서 스레드로 넘길 때 걸리는 것이 없다.
