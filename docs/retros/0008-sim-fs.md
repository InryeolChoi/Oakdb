# 0008. 가짜 파일시스템 — 회고

이슈 #20. 설계는 `docs/design/0008-sim-fs.md`, 실험은 `docs/experiments/0007-missing-syncs.md`. 검증 결과는 PR #52 코멘트에 있다.

## 만든 것

- **메모리 속 가짜 디스크 `SimFs`**: 엔진은 진짜 디스크인 줄 알고 그대로 쓴다. 파일마다 "읽기가 보는 내용"과 "sync한 내용"을 따로 들고, sync 사이의 쓰기는 줄을 세워 둔다.
- **`crash(seed)`**: sync 안 된 쓰기마다 남음·사라짐·찢김(512바이트 칸 단위)을 정하고, 디렉터리 sync 전에 만든 파일을 지울 수도 있다. 주사위는 직접 쓴 SplitMix64라서 같은 시드면 언제나 같은 디스크가 나온다.
- **`fail_after(n)`**: 디스크를 바꾸는 작업 n번 뒤 정전. 커밋 **도중**에 끊을 수 있다. 09번의 재료다.
- 파일시스템 계약 테스트 12개와 정답 모델 테스트를 진짜·가짜 양쪽에서 돌린다. 테스트 133개 → 167개.

## 배운 것

**진짜 디스크 위의 테스트는 sync가 없어도 모른다.** 실험 0007에서 엔진의 sync 호출을 하나씩 지웠더니, 진짜 디스크 테스트 수십 개가 거의 다 통과했다. 정전이 없으면 운영체제의 캐시가 늘 최신 내용을 돌려주기 때문이다. 하나를 잡은 것도 동작을 본 테스트가 아니라 "이 순서로 불렀다"를 적어 둔 테스트였다. 내구성은 **정전을 일으켜 봐야만** 보인다. 이번 티켓이 정전 안전 구간의 첫 번째인 이유다.

**정전 테스트는 "어디서 끊느냐"가 전부다.** 처음 쓴 엔진 정전 테스트는 커밋 20번을 다 한 뒤 정전을 일으켰고, "메타를 쓴 뒤 sync"를 지운 버그를 놓쳤다. 메타를 바꾼 커밋 다음에 오는 커밋의 sync가 앞 메타까지 금고에 넣어 줘서 버그가 가려졌다. 위험한 순간은 "메타를 바꾼 커밋 **직후**" 한 군데뿐이었다. 테스트를 "커밋 1~40번 각각의 직후"로 바꾸자 잡혔다. 같은 시드 200개를 돌려도 끊는 자리가 하나뿐이면 소용없다. 09번은 `fail_after`로 커밋 안의 **모든** 자리를 훑어야 한다.

**`todo!()`로 먼저 커밋하면 부산물이 생긴다.** 실패하는 테스트를 먼저 돌릴 때 proptest가 `todo!()` panic을 "찾아낸 실패"로 여겨 400KB짜리 회귀 파일을 저장했다. 진짜 버그가 아닌데 매번 먼저 재실행된다. 리뷰 두 개가 모두 짚었고 지웠다. 앞으로 실패하는 테스트를 커밋하기 전에 `git status`에서 회귀 파일이 새로 생겼는지 확인한다.

**재현 방법이 없는 숫자는 확인할 수 없다.** "변이 12개를 모두 잡음"과 실험 0007의 표는 맞는 숫자였지만, 어떤 줄을 지웠는지 적지 않아서 리뷰어가 다시 돌려 볼 수 없었다. 그때그때 쓰고 버린 스크립트를 `docs/experiments/scripts/mutants.py`로 저장소에 남겼다. 리뷰 반영 뒤 그 스크립트로 다시 돌린 결과가 문서와 같았다.

**"진짜와 똑같다"는 계약 테스트가 덮는 범위까지만이다.** 계약 9개는 모두 통과했지만, 리뷰는 그 바깥에서 다른 점 4개를 찾았다(아주 큰 offset이면 panic, 끝 너머 길이 0 읽기, 부모가 파일일 때의 오류 종류, sparse 파일). 3개는 계약에 더해 맞췄고, sparse는 메모리로는 흉내 낼 수 없어서 적어 두었다.

**Rust 쪽에서 눈여겨본 점**

- **잠금 포이즌**: 한 스레드가 잠금을 쥔 채 panic하면 `Mutex`는 "독이 든" 상태가 된다. 가짜 디스크의 변경은 모두 한 단계라서 panic이 나도 디스크가 반쯤 바뀌지 않는다. 그래서 `into_inner()`로 그대로 꺼내 쓴다. 특히 `Drop`에서 panic하면 이미 panic 중일 때 프로세스가 죽으므로 중요했다. 이 판단과 주석을 `lock()` 하나에 모았다.
- **`bool` 인자 대신 enum**: `self.with(false, …)`는 호출하는 쪽에서 `false`가 무엇인지 안 읽힌다. `Access::Read`/`Access::Change`로 바꾸자 호출 자리에서 뜻이 보인다. 주사위 결과 `0/1/_`도 `Landing::Lost/Kept/Torn`이 됐다. Java의 "boolean 매개변수 대신 enum"과 같은 이야기다.
- **`as` 대신 `try_from`·`checked_add`**: `offset as usize + len`은 큰 값에서 debug 빌드면 panic, release 빌드면 조용히 넘친다. `range()` 하나에서 검사하고 진짜 파일처럼 `InvalidInput`을 돌려준다.
- **복제본이 같은 디스크를 나눠 갖기**: `SimFs`는 `Arc<Mutex<Disk>>` 하나만 든 구조체라서 `clone()`이 디스크를 복사하지 않고 **같은 디스크를 가리키는 손잡이**를 하나 더 만든다. 테스트는 하나를 쥐고 하나를 엔진에 넘긴 뒤, 엔진을 버리고 `crash`를 부를 수 있다.
