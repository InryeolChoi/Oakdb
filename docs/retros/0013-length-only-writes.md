# 0013. 가짜 디스크: 길이만 닿고 내용은 0인 쓰기 — 회고

이슈 #56. 설계는 `docs/design/0013-length-only-writes.md`, 실험은 `docs/experiments/0012-length-only-writes.md`. 사용자가 자리에 없어 설계의 결정 8개를 추천안으로 진행했다. 모두 PR의 "판단할 것"에 있다.

## 만든 것

- **새 운명 `Landing::LengthOnly { zeros_from }`**: 쓸 때의 파일 끝을 넘는 쓰기가 정전 때 "새 길이만 닿음"으로 끝날 수 있다. 끝을 넘는 부분은 0, 안쪽 부분은 디스크에 있던 그대로다.
- **주사위를 늘리지 않음**: "사라짐"을 뽑은 끝 넘는 쓰기의 절반을 같은 주사위의 맨 위 비트로 "길이만"으로 바꾼다. 그 밖의 시드는 예전과 같은 디스크를 낸다.
- **`crash_sim`**: "길이만"·길이 변경의 운명·파일 이름을 찍고, 체크포인트 도중 정전을 제대로 이름 붙이고, `sweep`이 "길이만" 시드 수를 센다.
- **테스트**: SimFs 5개, 체크포인트 2개(정전이 20바이트 0 WAL을 직접 만듦), 고정 시드 2개(C3, C16).
- **엔진 코드는 바꾸지 않았다.** 새 고장에서 엔진 버그는 나오지 않았다.

| 검증 | 결과 |
|---|---|
| 실패하는 테스트 먼저 | db65c4a (새 테스트 5개 실패, 이 운명은 아직 안 나옴) |
| 정전 실험 | 10만 시드 100% (그중 12.9%에 "길이만"), 모든 시점 훑기 548개 깨짐 0 |
| 변이를 심은 정전 실험 | C16 811시드, C3 316시드 깨짐 (예전엔 둘 다 0) |

| 고정 시드 | 9개 중 8개는 디스크가 예전과 같음, 529만 바뀜 (여전히 통과) |
| CI macOS · Linux | PR에서 확인 |

## 배운 것

**"어느 시점의 끝"이냐가 고장 모델의 전부였다.** 처음 떠올린 모델은 "정전 때 디스크의 끝을 넘는 부분"이었다. 더 현실적으로 들렸다. 그런데 C3(비우기 뒤 sync 빼기)를 따라가 보니 그 모델로는 절대 안 깨진다. 비우기가 사라지면 머리말 쓰기는 옛 WAL **안쪽**이 되기 때문이다. "쓸 때 엔진이 본 끝"으로 재야 비우기와 머리말의 운명이 갈라지는 경우가 생긴다. 고장 모델을 고를 때 "실제 같은가"만 묻지 말고 "**어떤 버그를 드러내야 하나**"를 먼저 물어야 한다는 걸 배웠다. 대신 이 모델은 실제 저널보다 험할 수 있다는 것도 적어 두었다.

**시드는 공유 자원이다.** 주사위 하나를 더 던지면 그 뒤가 모두 밀려, 지난 실험 세 개의 표와 고정 시드 테스트가 한꺼번에 뜻을 잃는다. 같은 주사위 값의 다른 비트를 쓰니 87%의 시드가 그대로였다. "새 무작위 선택을 더할 때는 기존 선택을 쪼개 쓴다"는 결정적 시뮬레이션의 습관으로 가져간다.

**실험이 이제 리뷰가 찾은 걸 스스로 찾는다.** PR #55의 P1은 사람이 코드를 읽고 찾았다. 이번에 P1 수정을 빼고 정전 실험을 돌리니 10만 중 811시드가 깨졌다. 그동안 "실험 100%"는 엔진이 튼튼해서가 아니라 **디스크가 친절해서**였던 부분이 있었다.

**작업 표의 이름표도 틀릴 수 있다.** `crash_sim one`이 체크포인트 도중 정전을 "while opening"으로 찍고 있었다. 커밋 사이의 정전을 모두 "열기"로 본 탓이다. C3 사례를 읽으려다 알았다. 도구의 출력도 검증 대상이다.

**Rust 쪽에서 눈여겨본 점**

- **enum 변형 하나가 모든 `match`를 찾아 준다**: `Landing`에 변형을 더하자 컴파일러가 `sim.rs`, `crash_sim`, 테스트의 `match`를 전부 짚었다. 실패하는 테스트 커밋에서는 변형만 더하고 `unreachable!`로 막아 두어 테스트가 컴파일은 되고 실행에서 실패하게 했다.
- **`Option::then`으로 "해당할 때만 값"**: `(end > old_len).then(|| offset.max(old_len))`가 "끝을 넘는가"와 "어디부터 0인가"를 한 줄에 담는다. `then_some(offset)`(값을 미리 계산)과 `then(|| …)`(필요할 때 계산)의 차이를 변이 하나로 썼다.
- **패턴 가드로 확률 쪼개기**: `0 => match zeros_from { Some(z) if draw >> 63 == 1 => …, _ => Lost }`. 가드가 거짓이면 다음 갈래로 떨어지는 성질 덕분에 "해당 안 되면 예전 그대로"가 코드 모양으로 보인다.
- **변경에 그때의 상태를 같이 저장**: `Change::Write`에 `old_len`을 넣었다. 정전 때 다시 계산하면 이미 다른 상태라 답이 달라진다. 이벤트를 기록할 때 판단에 필요한 맥락도 함께 기록해야 한다.

## 다음 이슈로 넘기는 것

- **늘어난 자리에 옛 블록 내용이 보이는 경우**: ext4 writeback은 0 대신 쓰레기를 보일 수 있다. 옛 WAL 머리말이 다시 보이는 것 같은 경우를 만든다. 새 이슈 후보.
- **`mutants.py`가 첫 실패 파일에서 멈춤**: cargo 기본 동작이라 `crash.rs`가 잡는지는 보이지 않는다. `--no-fail-fast`로 바꾸면 느려진다. 필요할 때 정한다.
- **#24**: 전원이 켜진 채 쓰기·sync 실패 주입 (다른 에이전트가 진행 중).
