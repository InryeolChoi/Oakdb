# 0009. 정전 실험 — 회고

이슈 #21. 설계는 `docs/design/0009-crash-experiment.md`, 실험은 `docs/experiments/0008-power-cuts.md`. 검증 결과는 PR #53 코멘트에 있다.

## 만든 것

- **`crash_sim` 예제**: 시드 하나로 "작업 → 커밋 도중 아무 데서나 정전 → 다시 열기 → 판정"을 재현한다. `one`(한 시드), `sweep`(여러 시드), `every`(한 작업의 모든 정전 시점) 세 명령.
- **판정기 `judge`**: 키마다 "응답한 값 / 정전에 걸린 커밋의 값 / 실제 값"을 비교해 약속을 지켰는지, 어떻게 깨졌는지 이름을 붙인다. 순수 함수라 가짜 상태로 단위 테스트했다.
- **가짜 디스크에 `ops()`와 `CrashReport`**: 정전 시점을 고를 작업 카운터와, sync 안 된 쓰기마다 남음·사라짐·찢김(칸별)을 적은 보고서.
- **회귀 테스트**: 깨지는 방식마다 시드 하나씩 `#[ignore = "needs the WAL (#22)"]`로 7개. 10번에서 `ignore`만 떼면 "고쳐졌다"의 증거가 된다.
- **엔진 버그 하나 고침**: 다시 열 때 빈 페이지 목록이 사용 중인 페이지를 가리키면 debug 빌드가 panic했다. 이제 거절한다.

## 배운 것

**지금 설계는 "응답한 커밋"은 지키지만 "다시 열린다"를 못 지킨다.** 절반 가까이가 열기 거절이다. 응답한 커밋이 사라진 적은 없다. sync한 뒤에 OK를 주는 규칙 덕분이다. 그런데 다음 커밋이 반쯤 쓰이면 DB 전체가 열리지 않아서, 응답한 커밋도 결국 읽을 수 없다. "데이터가 디스크에 있다"와 "데이터를 꺼낼 수 있다"는 다른 약속이다.

**"메타를 마지막에 쓰면 안전하다"는 덮어쓰지 않을 때만 맞다.** 시드 159는 디스크가 아무것도 잃지 않았는데도 깨졌다. 페이지는 모두 sync됐고 메타만 못 썼다. 새 페이지가 옛 페이지를 제자리에서 덮어썼으니, 옛 메타가 가리킬 옛 페이지가 이미 없다. 마지막 한 장을 바꿔서 전환하려면, 그 전까지는 옛것을 건드리면 안 된다. WAL(또는 copy-on-write)이 필요한 이유가 한 문장으로 정리됐다.

**검사를 잘 해 둔 덕에 대부분 시끄럽게 실패한다.** 07번 체크섬과 04·06번 구조 검사가 거의 모든 실패를 "열기 거절"로 바꿨다. 조용히 틀린 값을 돌려준 건 반쪽 커밋 하나뿐이다(2.8%). 페이지 하나하나는 멀쩡하고 서로 어긋날 뿐이라, 페이지 단위 검사로는 잡을 수 없다. 커밋을 한 덩어리로 남기는 로그만이 해결한다.

**실험 도구가 엔진 버그를 찾았다.** "응답한 커밋은 사라지지 않는다"를 상시 테스트로 두었더니 debug 빌드에서 panic이 났다. 처음 훑기는 release로 돌려서 못 봤다. `debug_assert`는 release에서 사라지므로, **빌드 종류가 실험 조건의 일부**다. 실험 문서 맨 위에 빌드 종류를 적었다.

**주석이 거짓말을 하면 리뷰도 속는다.** `chain()`의 주석은 "앞 페이지를 받은 뒤에야 다음 페이지를 읽는다"였다. `std::iter::successors`는 반대로, 지금 페이지를 돌려주기 **전에** 다음 값을 계산한다. 06번 리뷰는 주석을 믿고 넘어갔다. 고친 뒤 주석도 "검사가 끝난 사슬에만 쓴다"로 바꿨다.

**판정할 자격이 있는지부터 확인해야 한다.** 리뷰가 짚은 점: 하네스는 커밋이 실패하면 이유를 묻지 않고 "정전에 걸린 커밋"으로 봤다. 정전과 무관한 오류였다면 전원이 켜진 채 판정이 틀어진다. 이제 `ops() == cut_after`가 아니면 멈춘다. 1만 개 시드에서 한 번도 걸리지 않았지만, 걸리지 않는다는 것을 이제는 **확인**한다.

**Rust 쪽에서 눈여겨본 점**

- **`std::iter::successors`의 계산 시점**: 반복자는 `next()`에서 지금 값을 꺼내며 다음 값을 미리 계산해 둔다. 다음 값을 계산하는 데 "지금 값이 올바른지"가 전제라면 쓰면 안 된다. 검사하는 쪽은 `while let Some(page_no) = next { 확인; next = page.next(); }`처럼 순서를 손으로 쓰는 편이 정확하다.
- **`catch_unwind`와 `AssertUnwindSafe`**: 다시 열기를 `catch_unwind`로 감싸 panic을 판정 하나(`Panicked`)로 바꿨다. `AssertUnwindSafe`는 "panic 뒤에 반쯤 바뀐 값을 읽지 않는다"는 약속이다. 여기서는 panic 뒤에 가짜 디스크만 남고, 디스크의 변경은 한 단계라 반쯤 바뀌지 않는다.
- **panic 훅 고르기**: 시드 1만 개를 돌릴 때 엔진 panic 메시지를 다 찍으면 화면이 넘친다. 그렇다고 훅을 통째로 끄면 하네스 자신의 단정 실패도 조용히 사라진다. `PanicHookInfo::location()`으로 panic이 난 파일을 보고, 하네스 쪽만 그대로 출력한다.
- **문자열에 다시 `match`하지 않기**: `kind()`가 문자열을 만들고 `label()`이 그 문자열에 다시 `match`하면서 `unreachable!()`이 필요했다. enum에 바로 `match`하고 가드(`if creating`)를 쓰니, 새 판정 종류를 더할 때 컴파일러가 빠진 곳을 알려 준다.
- **튜플 대신 이름 있는 구조체**: `(u64, Option<(u64, u64)>)`를 `.0`/`.1`로 다루던 것을 `Count { seeds, shortest: Option<Shortest { seed, cut_after }> }`로 바꿨다. 패턴으로 풀 때 이름이 그대로 읽힌다.
