# 0011. 체크포인트와 메타 슬롯 두 개 — 회고

이슈 #23. 설계는 `docs/design/0011-checkpoint.md`, 실험은 `docs/experiments/0010-power-cuts-with-checkpoints.md`. 검증 결과는 PR #55 코멘트에 있다.

## 만든 것

- **체크포인트**: WAL에 있는 페이지 → 장부 제자리 → sync → 새 회차 메타를 오래된 슬롯에 → sync → WAL 비우기 → sync → 머리말 → sync. 커밋 뒤 WAL이 4MiB를 넘을 때와 `close()`에서, 그리고 `Db::checkpoint()`로.
- **형식**: 메타 페이지 형식 4에 회차, WAL 앞에 20바이트 머리말. 사슬 체크섬이 머리말에서 시작해서 다른 회차의 레코드는 끼어들지 못한다.
- **열기**: 성한 슬롯 중 회차가 큰 쪽과 WAL 머리말의 회차를 맞춰 본다(`choose_base`). 같으면 재생, 작으면 버림, 크면 거절.
- **실패하면 정지**: 정리가 실패하면 그 뒤 커밋과 정리를 거부한다. 다시 열면 복구된다.
- #22에서 미룬 테스트 10개를 다시 켰다.

## 배운 것

**두 검증이 따로 같은 구멍을 찾으면 그건 진짜다.** 20바이트 WAL 머리말(P1)을 Spec 리뷰어는 코드를 읽고, 눈 가린 테스터는 설계 문장("머리말 길이 **이하**")만 보고 찾았다. 서로의 결과를 모른 채였다. 정전 실험 10만 시드와 변이 검사는 이 구멍을 못 봤다. 설계 문서에 "이하"라고 써 놓고 코드는 "미만"으로 짰는데, 내 테스트도 0·1·19바이트만 골랐다. 경계값 테스트를 짤 때는 **경계 그 자체**(정확히 20)를 넣어야 한다.

**가짜 디스크가 못 만드는 고장은 여전히 남는다.** 0010에서 배운 것("테스트는 고장 모델의 범위까지만 증명한다")이 이번에 다른 모양으로 나왔다. SimFs는 찢어진 쓰기가 파일 길이를 늘리지 않는다. 실제 파일 시스템은 "길이는 닿고 내용은 0"을 남길 수 있다. 그래서 P1을 실험이 못 찾았고, 그 수정이 기대는 sync(C3)를 빼도 테스트가 안 깨진다. 다음에 고칠 곳은 엔진이 아니라 가짜 디스크다.

**넘침은 한 자리만 막으면 옆에서 또 터진다.** 리뷰가 짚은 건 `page_count × 4096` 하나였다. 사용자가 "타입을 넓혀서" 고치자고 했고, 넓히는 건 그 자리만 막는다는 걸 알았기에 "디스크에서 읽은 숫자가 계산에 쓰이는 모든 자리"를 표로 훑었다. 그러다 리뷰가 못 본 `checkpoint + 1`을 찾았다. 이건 더 위험했다. release에서 0으로 감기면 새 표지가 옛 표지에 지고, 다음 열기가 WAL을 "옛것"으로 버려 **응답한 커밋이 오류 없이 사라진다**. panic보다 조용한 손실이 더 나쁘다. 실패하는 테스트를 먼저 짜 보니 debug에서 정확히 그 두 줄에서 panic이 났다.

**검사는 쓰기 전에.** 회차 검사를 처음엔 페이지를 장부에 다 쓴 뒤에 넣었다. 안전하긴 했다(① 도중 정전과 같은 상태). 하지만 0010의 "파괴적인 일은 검사 뒤에"와 같은 원리로, 거절할 거라면 아무것도 쓰기 전에 거절하는 쪽이 따질 상태가 적다.

**잠금 순서는 정확성 문제다.** "정리 중에 읽기가 막힌다"(S6·P7)를 고치려고 트리 사본을 잡고 잠금을 풀면, 그 사이 커밋이 WAL에 들어갔다가 정리의 WAL 비우기에 지워진다. 순서를 바꾸면 커밋과 교착된다. 성능 개선처럼 보이는 일이 데이터 손실이 될 수 있어서 #27(커밋 스레드)로 미뤘다.

**Rust 쪽에서 눈여겨본 점**

- **넘침 처리 세 가지**: `u128`로 넓혀서 비교(`pages_len`), `checked_add`로 넘침을 `Option`으로 받아 오류로 바꾸기, 범위가 보장된 자리는 `checked_mul(...).expect("이유")`로 불변식을 적기. debug의 panic과 release의 감김이 다르게 동작한다는 걸 테스트를 **release로도** 돌려 확인했다.
- **`bool` 대신 enum**: `replay: bool`이 두 군데서 `match true/false`, `if replay && …`로 갈라졌다. `UseWal::{Replay, Restart}`로 바꾸니 각 갈래가 무슨 뜻인지 이름이 말해 준다. 판단 자체도 `choose_base`라는 순수 함수로 빼서 파일 없이 단위 테스트할 수 있게 됐다.
- **패턴 매치로 오류 종류 고르기**: `(Err(Error::Corrupt(_)), Some(0)) if wal_has_commit`처럼 오류의 **종류**까지 패턴에 넣어, 손상만 넘기고 I/O 오류나 페이지 크기 불일치는 그대로 올려 보낸다(P2).
- **`#[expect(dead_code)]`가 할 일을 했다**: #22에서 남긴 `expect(dead_code)` 셋은 이번에 코드를 쓰기 시작하자 경고로 "지우라"고 알려 줬다.
- **`Rc<Cell<bool>>`로 고장 주입**: 실패 뒤 엔진 정지를 시험하려고 "sync 한 번만 실패하는" `Fs` 래퍼를 테스트에 만들었다. 단일 스레드 테스트라 `Arc<Mutex>` 대신 `Rc<Cell>`이면 충분하다.

## 다음 이슈로 넘기는 것

- **가짜 디스크에 "길이만 닿고 내용은 0" 고장 더하기**: P1과 C3가 이 모델 밖이었다. 사용자 결정이 필요하다 (PR #55).
- **#24**: 커밋 경로의 sync 실패 뒤 엔진 정지, "엔진 정지" 전용 오류 종류(S5).
- **#27**: 정리 중 읽기가 막히는 문제(S6·P7).
- **필요한 페이지만 읽는 열기**: 재시작 시간에서 장부 전체를 읽는 부분(P4). 지금은 트리 전체가 메모리에 있다.
- **정리를 맡은 커밋의 꼬리 지연**: 평균에는 안 보였다. 그룹 커밋 벤치마크에서 함께 잰다.
