# 0012. 디스크 기록 실패 처리 — 회고

이슈 #24. 설계는 `docs/design/0012-disk-failure.md`, 실험은 `docs/experiments/0011-disk-failure.md`. 사용자가 자리에 없는 동안 진행해서, 설계 결정 7개는 모두 "추천안으로 진행 · 사용자 확인 필요"로 PR에 올렸다.

## 만든 것

- **엔진 정지**: 엔진이 열린 뒤 쓰기·길이 바꾸기·sync가 실패하면 `Db`가 멈춤 원인을 `OnceLock`에 한 번 적는다. 쓰는 쪽은 트리 잠금을 쥔 **뒤** 확인한다.
- **오류 두 종류**: 실패를 만난 커밋은 `Error::OutcomeUnknown(io::Error)`, 그 뒤의 모든 요청(읽기 포함)은 `Error::Stopped(Arc<Error>)`. #23의 "정리 실패 = `Io(other(..))`"(리뷰 S5)를 대신한다.
- **자동 정리가 실패한 커밋은 `Ok`**: WAL에 sync까지 끝났으니 남는다. 엔진만 멈춘다.
- **가짜 디스크의 한 번 실패**: `SimFs::fail_once_after(n)`. 테스트에 따로 있던 `FlakyFs`(sync 한 번 실패 래퍼)를 지웠다.
- `Wal`의 `stopped`·`stop`·`check_running`을 지우고 멈춤을 `Db` 한 곳으로 모았다.

## 배운 것

**"다시 해 보기"는 코드에 안 보이는 곳에 숨어 있었다.** #22의 커밋은 실패하면 꼬리를 그대로 두고 오류를 돌려줬다. 재시도 루프는 어디에도 없었다. 그런데 다음 커밋이 같은 자리에 다시 쓰고 sync하니, 그게 곧 재시도였다(설계 0010 2절이 이미 "사실상 재시도"라고 적어 두었다). 재시도를 막는다는 건 루프를 지우는 게 아니라 **"실패 뒤의 다음 요청"을 막는 것**이었다.

**확인하는 자리가 정확성을 정한다.** 처음 떠오른 건 각 함수 맨 앞에서 "멈췄나?"를 보는 것이었다. 그러면 커밋 B가 확인을 통과하고 잠금을 기다리는 사이 커밋 A가 실패했을 때, B가 잠금을 얻고 WAL에 또 쓴다. 한 스레드 테스트로는 이 경쟁을 만들 수 없어서, "실패 **전에** 시작해 둔 트랜잭션을 실패 **뒤에** 커밋"으로 같은 순서를 만들었다. 변이 F5(잠금 뒤 확인을 뺌)를 그 테스트가 잡았다.

**변이 검사가 테스트의 이름을 거짓말로 만들었다.** `a_power_cut_comes_first_if_both_are_due`는 "정전이 이긴다"를 시험한다고 이름 붙였지만, 실제로는 "다음 호출도 실패한다"만 봤다. 한 번 실패 뒤에도 정전이 곧 와서 다음 호출이 실패하니, 순서가 바뀌어도(S3) 통과했다. 정전과 한 번 실패를 가르는 건 **읽기**였다. 정전이면 읽기도 실패하고, 한 번 실패면 읽기는 된다. 한 줄을 더하니 잡혔다.

**"결과를 알 수 없음"도 시험할 수 있다.** 실패한 커밋이 다시 열면 있어도 되고 없어도 된다. 그래서 "있거나 없음"만 확인하면 언제나 "없음"만 나오는 버그(예: 실패한 커밋을 열 때 늘 버림)도 통과한다. 커밋 훑기에서 **둘 다 한 번 이상 나오는지**를 함께 확인했다. 정전 없이 다시 열면 sync가 실패한 바이트가 캐시에 있어서 "있음", 쓰기가 실패하면 "없음"이 나온다.

**가짜 디스크가 정한 범위까지만 증명한다 (세 번째).** 0010의 찢긴 쓰기, 0011의 "길이만 닿음"(#56)에 이어 이번에는 "sync가 실패한 페이지가 캐시에 깨끗함으로 남음"이다. 같은 부팅에서 다시 열면 디스크에 없는 바이트를 읽고 그 뒤에 새 커밋을 붙인다. 가짜 디스크는 실패한 sync의 변경을 "계속 기다림"으로 둬서 나중 sync가 살려 준다. 그래서 이 구멍은 테스트로 드러나지 않는다. 설계 문서에 선택지(열기 끝 정리, 캐시 우회 읽기)를 적고 별도 티켓으로 넘겼다.

**Rust 쪽에서 눈여겨본 점**

- **`OnceLock<Arc<Error>>`**: "한 번 정해지면 바뀌지 않는다"가 타입으로 드러난다. `set`이 두 번째부터 실패하므로 첫 원인이 남는다. 읽기는 잠금 없이 `get()` 한 번이다.
- **복제할 수 없는 `io::Error`**: 멈춘 뒤 모든 요청이 같은 원인을 돌려줘야 하는데 `io::Error`는 `Clone`이 아니다. 실패한 호출은 원래 오류를 갖고, 멈춤 표시는 종류(`kind`)와 메시지가 같은 사본을 `Arc`로 나눠 쥔다. `source()`로 원인 사슬도 이어진다.
- **`#[non_exhaustive]`가 값을 했다**: `Error`에 종류 둘을 더해도 쓰는 쪽 `match`가 깨지지 않는다. 처음부터 붙여 둔 덕이다.
- **`inspect_err`**: `map_err(|e| { self.stop(&e); e })`를 clippy가 `inspect_err(|e| self.stop(e))`로 바꾸라고 했다. 오류를 바꾸지 않고 들여다보기만 한다는 뜻이 이름에 있다.
- **반복자에 오류 하나 끼우기**: `scan`은 `Result`가 아니라 `Scan`을 돌려준다. 공개 API를 바꾸지 않으려고 `Scan`에 `stopped: Option<Error>`를 두고, 빈 범위로 만든 뒤 `next()`가 처음 한 번 `take()`해서 돌려준다. `FusedIterator` 약속도 그대로다.

## 다음 이슈로 넘기는 것

- **같은 부팅에서 다시 열 때의 캐시 구멍** (설계 0012 결정 7): 가짜 디스크에 "sync 실패 = 캐시엔 새 내용, 디스크엔 옛 내용, 나중 sync도 못 살림" 고장을 더하고, 열기 끝 정리나 캐시 우회 읽기를 고르는 티켓을 제안한다.

- **#56**: C3는 여전히 놓친다. 가짜 디스크의 "길이만 닿음" 고장 모델 몫이다.
