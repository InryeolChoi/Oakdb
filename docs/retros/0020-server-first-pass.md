# 0020. 서버 첫 관통: 통신 규칙과 CLI — 회고

이슈 #36. 설계는 `docs/design/0020-server-first-pass.md`, 통신 규칙 참조는 `docs/protocol.md`, 접속 처리 결정은 ADR 0010. S1~S12는 추천안대로 정했고 두 군데를 사용자가 바꿨다. S1에는 **"손님 수백 명도 감당"** 요구가 더해졌고, S8의 `--host`는 **허용 목록**으로 바뀌었다.

## 만든 것

- **`oakdb` 실행 파일 하나, 하위 명령 둘**:
  - `oakdb serve --data <디렉터리> [--port] [--allow]... [--allow-file] [--max-connections]`
  - `oakdb cli [--host] [--port]`
- **서버 크레이트를 라이브러리로**: `protocol`(프레임), `allow`(허용 목록), `rlimit`(파일 기술자 한도), `server`(접속마다 스레드), `client`, `cli`(문장 자르기·표 출력). `main.rs`는 옵션만 읽는다.
- **통신 규칙 버전 1**:
  - 프레임은 `[길이 u32 BE][명령 u8][데이터]`, 최대 16 MiB.
  - 접속 직후 HELLO/READY로 인사한다.
  - 응답은 ROWS·AFFECTED·DONE·ERROR. ROWS의 값은 SQL 층의 행 값 인코딩(0017 2-2절)과 같은 모양이다.
  - 오류 코드는 범위로 묶었다: 문장 `0x01–0x1F`, 엔진 `0x20–0x3F`, 통신 `0x40–0x5F`.
- **수백 접속**:
  - 상한 512(넘으면 `0x45` 후 끊음). 접속 스레드 스택은 256 KiB.
  - 시작할 때 파일 기술자 soft 한도를 `상한 + 64`까지 올리고, 안 되면 시작을 거부한다.
- **허용 목록**:
  - IPv4 주소·CIDR, 루프백은 항상 허용.
  - 목록이 없으면 127.0.0.1에만 연다. 목록에 없는 주소는 `0x46` 후 끊는다.
  - 인증이 아니라는 점을 `--help`와 `docs/protocol.md`에 적었다.

## 배운 것

**"수백 명"은 스레드보다 파일 기술자 문제였다.** 스레드 300개는 아무 일도 아니었다. 막히는 곳은 macOS의 기본 soft 한도 256이다. 접속 하나가 소켓 하나, 곧 파일 기술자 하나라서, 손님 250명쯤에서 `accept`가 `EMFILE`로 실패하기 시작한다. 그래서 서버가 시작할 때 `setrlimit`으로 soft 한도를 올린다. soft 한도는 권한 없이 hard 한도까지 올릴 수 있다. macOS는 hard 한도가 "무제한"이어도 `OPEN_MAX`(10240)를 넘는 값은 거부해서 그 안으로 맞췄다. 테스트는 서버 300 + 클라이언트 300을 한 프로세스에서 열어서 한도를 2048로 올린다. 식당으로 치면 의자(스레드)보다 **전화선(기술자) 개수**가 먼저 모자랐다.

**거절도 예의 있게 닫아야 전달된다.** 서버가 "자리 없음" 오류를 쓰고 바로 소켓을 닫으면, 클라이언트가 이미 보낸 HELLO가 서버 쪽에 읽히지 않은 채 남는다. 읽지 않은 데이터가 남은 소켓을 닫으면 TCP는 정상 종료(FIN) 대신 **리셋(RST)**을 보낸다. 그러면 클라이언트는 오류 프레임을 읽기 전에 "connection reset"을 받을 수 있다. 그래서 닫기 전에 쓰기 쪽만 먼저 닫고(`shutdown(Write)`), 남은 입력을 읽어 버린 뒤 닫는다(lingering close). 접속을 받는 스레드에서 거절할 때는 기다리지 않고 이미 와 있는 것만 비운다. 한 손님 때문에 문 앞 줄 전체가 서면 안 되기 때문이다.

**엔진의 규칙이 서버 테스트에도 그대로 보인다.** 8개 접속이 동시에 `CREATE TABLE`을 하면 모두 표 번호 카운터 키 `[00]`을 쓴다. 그래서 첫 커밋 하나만 이기고 나머지는 충돌(`0x20`)로 진다(0017 6절). 테스트에 "충돌이면 한 번 더"를 넣었는데 8개 중 여럿이 연달아 져서 실패했다. "될 때까지 다시"로 고쳤다. `0x20`의 뜻("다시 하면 될 수 있다")이 실제로 클라이언트 코드 모양을 정했다.

**테스트의 가정도 틀린다.** `SELEC 1`이 문법 오류(`0x01`)일 줄 알았는데 SQL 층은 "지원 안 함"(`0x02`)으로 답했다. 모르는 단어로 시작하는 문장은 "지원 안 함"이 맞다(0017). 닫는 괄호가 없는 INSERT로 바꿨다. 0017 회고의 "지원 안 함과 문법 오류의 경계는 흐리다"가 다시 나왔다.

**길이 칸을 믿지 않는 것이 이진 규칙의 핵심이다.** 길이 4바이트만 보고 그만큼 메모리를 잡으면 `GET /`(HTTP 요청)이 1.2 GB 할당이 된다. 그래서 본문을 읽기 전에 16 MiB와 비교한다. ROWS를 읽을 때도 "열 0개에 행 40억 개" 같은 작은 프레임이 큰 반복을 만들 수 있어서 따로 막았다. 무작위 바이트 속성 테스트가 이런 구멍을 지킨다.

**Rust 쪽에서 눈여겨본 점**

- **자리 세기를 RAII로**: `Slot`은 만들 때 접속 수를 올리고 drop될 때 내린다. 스레드가 정상으로 끝나든, 패닉하든, 아예 못 만들어지든(클로저가 drop됨) 자리가 돌아온다.
- **`Server<F: Fs>` + `where Db<F>: Send + Sync`**: 엔진이 이미 `Fs`에 제네릭이라 서버도 그대로 따라갔다. 덕분에 가짜 디스크(`SimFs`)로 "디스크 실패 뒤 서버가 `0x25` → `0x26`으로 답한다"를 종단 테스트로 확인했다.
- **`std`만으로 충분했다**: TCP, 스레드 스택 크기(`thread::Builder::stack_size`), 터미널 판별(`IsTerminal`) 모두 표준 라이브러리에 있다. 표준 라이브러리에 없는 것은 `setrlimit` 하나뿐이라 엔진이 이미 쓰는 `libc`만 더했다.
- **실행 파일 이름과 라이브러리 이름 충돌**: 실행 파일 `oakdb`와 엔진 라이브러리 `oakdb`가 `cargo doc`에서 부딪힐 수 있어 `[[bin]] doc = false`로 껐다.
