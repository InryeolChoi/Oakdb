# 0003. 첫 분할: 2층 트리 — 회고

이슈 #15. 설계는 `docs/design/0003-first-split.md`, 실험은 `docs/experiments/0004-crash-in-a-multi-page-commit.md`, 벤치마크는 `docs/benchmarks/0003-two-level-tree.md`.

## 만든 것

- **내부 페이지**: 리프와 같은 배치를 쓰고, 셀의 값 자리에 자식 페이지 번호를 넣는다.
- **리프 분할**: 바이트가 반씩 되게 나누고, 루트가 없으면 만들고, 있으면 루트에 구분 키를 더한다. 옆 포인터도 이어 준다.
- **`Tree` 모듈**: 페이지를 `Arc`로 나눠 갖는 메모리 속 트리다. 커밋은 바꾼 페이지만 복사하고(copy-on-write), 그 페이지만 쓴다.
- **열 때 트리 검사**: 자식 범위, 두 번 닿는 페이지, 키 범위, 리프 깊이, 옆 포인터 사슬을 본다.
- **`ValueTooLarge`**: 키+값이 1006바이트를 넘으면 거부한다. overflow(#18) 전까지의 제한이다.
- 테스트 65개(단위 35, 통합 30). 새로 넣은 것: 분할 통합 테스트 7개, 트리 단위 테스트 8개. 무작위 put/delete 테스트는 키 200개로 넓혀서 분할이 일어나게 했다.
- 일부러 버그를 6가지 심어 봤고(변이 검사), 모두 테스트가 잡았다.

## 배운 것

**"한 장"이라는 가정은 생각보다 많은 곳에 숨어 있었다.** 분할 코드 자체보다 기존 코드를 고치는 일이 더 많았다.

- 실험 도구 둘은 "`PageFull`이 날 때까지" 돌았다. 분할이 생기면 이 조건이 오지 않아 끝없이 돈다.
- 벤치마크도 같은 이유로 바꿨다.
- 테스트 몇 개는 "3000바이트 값"을 썼는데, 이제는 크기 제한에 걸린다.
- 테스트 몇 개는 "안 들어가면 `PageFull`"로 공간 재사용을 확인했다. 이제는 공간이 모자라면 분할이 일어나서 이 확인이 통하지 않는다. 그래서 **파일 크기가 늘지 않았는지**(= 분할이 없었는지)로 바꿨다. 02번의 커밋 순서 테스트도 같은 방식으로 살렸다. 지금도 키 순서대로 적용하는 코드로 되돌리면 이 테스트가 잡는다.

**리프와 내부 페이지를 같은 배치로 둔 것이 가장 큰 절약이었다.** 내부 페이지를 따로 만들었다면 탐색, 넣기, 정리, 손상 검사를 다시 써야 했다. "값 자리에 페이지 번호"라는 SQLite의 선택 덕분에 새로 쓴 것은 자식 찾기(`child_index`, `child_at`, `set_child_at`)와 분할뿐이었다.

**예상과 다른 실험 결과가 가장 많은 것을 알려 줬다.** 분할 중 멈추면 "오른쪽 절반의 키를 조용히 잃는다"고 예상했다. 실제로는 DB가 **열리지 않았다.** 열 때 검사하는 옆 포인터 사슬이 "파일 밖을 가리키는 리프"를 잡았기 때문이다. 검사는 #17(범위 조회)을 위해 넣은 것인데, 손상을 알아차리는 데도 쓰였다. 다만 알아차릴 뿐 고치지는 못한다. 또 리프 두 장에 걸친 커밋은 구조가 멀쩡해서 **어떤 검사로도 잡을 수 없는** 반쪽 커밋을 남겼다. "구조 검사"와 "원자성"은 다른 문제라는 것을 다시 확인했다(01번 실험의 교훈과 같다).

**페이지가 두 장이 되는 순간 정전이 아니어도 깨진다.** 01·02번에서는 커밋이 페이지를 한 장만 써서, 프로세스가 죽어도 "전부 아니면 전무"였다. 한 장이 반만 써지는 일은 정전 때만 생긴다. 분할은 처음으로 "여러 장을 다 써야 한 커밋"을 만들었고, 프로세스가 중간에 죽는 것만으로도 원자성이 깨진다. WAL이 왜 필요한지가 01번 실험(정전)보다 이번 실험(프로세스 중단)에서 더 분명해졌다.

**Rust 쪽에서 눈여겨본 점**

- `Arc::make_mut`가 copy-on-write를 한 줄로 해 준다. 커밋 중인 복사본이 가진 페이지를 고치려 하면, 원본 트리와 나눠 갖고 있을 때만 복사한다. 01번의 "복사본을 고치고 바꿔 끼운다"가 페이지 단위로 자연스럽게 넓어졌다.
- `Rc` 대신 `Arc`를 쓴 이유는 `Db`가 `Sync`여야 해서다. `Mutex<Tree>` 안에 `Rc`가 있으면 `Db`를 여러 스레드가 나눠 쓸 수 없다. 스레드 티켓(#27)을 위해 지금부터 지켜 둔다.
- 크기 제한의 근거(4개가 한 장에 들어간다)를 `const _: () = assert!(...)`로 컴파일할 때 검사하게 했다. `footprint`를 `const fn`으로 만들어야 했다.
- 열 때 하는 트리 검사는 재귀로 짰다. 높이가 2라 깊이 걱정이 없지만, 손상된 파일에서 무한 재귀가 나지 않는 것은 "두 번 닿는 페이지 거부" 덕분이다.

## 다음 이슈로 넘기는 것

- **#16 (여러 층 트리)**: 루트가 차면 지금은 `PageFull`이다. 내부 페이지 분할을 넣으면 이 오류가 사라진다. 그때 무작위 모델 테스트를 큰 키로도 돌린다.
- **#21·#22 (정전 실험, WAL)**: 실험 0004의 두 경우(분할 중 중단, 두 리프 커밋 중 중단)를 재현 도구와 함께 넘긴다.
- **#18 (overflow)**: `ValueTooLarge`를 overflow 페이지로 바꾼다.
- **오름차순 넣기의 반쯤 빈 리프**: 순서대로 넣으면 왼쪽 리프가 반만 찬 채로 남는다. 벤치마크에서 문제가 보이면 SQLite처럼 오른쪽 끝 분할을 치우치게 한다.
