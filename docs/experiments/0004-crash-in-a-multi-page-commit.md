# 0004. 페이지를 여러 장 쓰는 커밋이 중간에 멈추면

이슈 #15의 검증 기록이다.

- 환경: macOS (Apple silicon), APFS, debug 빌드
- 도구: `crates/oakdb/examples/multi_page_crash.rs`

**질문**: 01번까지 커밋은 페이지를 한 장만 썼다. 분할이 생기면서 커밋 하나가 페이지를 여러 장 쓰게 됐다. 그 사이에 프로세스가 죽으면 어떻게 될까?

```sh
cargo run --example multi_page_crash -- /tmp/oak-exp4
```

정전이 아니라 **프로세스가 죽는 경우**를 흉내 냈다. 정해진 횟수만큼 쓰기를 통과시킨 뒤, 그다음 쓰기부터는 모두 실패하는 가짜 파일시스템을 끼웠다. 운영체제 캐시에 들어간 쓰기는 프로세스가 죽어도 남으므로, 결과는 "앞의 몇 장만 쓰고 죽은" 상태와 같다.

## 경우 1: 분할하다 메타 페이지 앞에서 멈춤

리프 하나를 꽉 채운 뒤(키 36개), 분할을 일으키는 37번째 키를 커밋했다. 분할 페이지 세 장(왼쪽, 오른쪽, 새 루트)은 쓰고, 메타 페이지 앞에서 멈췄다.

| 시점 | 파일 페이지 수 | 다시 열면 |
|---|---|---|
| 분할 전 | 3 | 커밋한 키 36개 모두 있음 |
| 멈춘 뒤 | 5 | **열리지 않음**: `leaves do not point to the next leaf` |

파일을 직접 열어 보니:

- 메타는 여전히 "루트는 페이지 2, 페이지는 3장"이다.
- 그런데 페이지 2는 이미 **왼쪽 절반(키 18개)** 으로 덮어써졌고, 옆 포인터는 페이지 3을 가리킨다.
- 메타 기준으로 페이지 3은 파일 밖이다. 트리 검사가 "마지막 리프가 어딘가를 가리킨다"를 잡아내 열기를 거부했다.

**옆 포인터 검사가 없었다면** 이 DB는 문제없이 열리고 키 18개만 보였을 것이다. 커밋이 끝난 키 18개가 **조용히 사라진** 것이다. 지금은 "열리지 않음"으로 시끄럽게 실패하지만, 고칠 방법은 없다.

## 경우 2: 리프 두 장을 고치는 커밋이 한 장만 쓰고 멈춤

리프가 둘인 트리에서 한 트랜잭션으로 왼쪽 리프의 키 0과 오른쪽 리프의 키 36을 함께 바꿨다. 첫 페이지만 쓰고 멈췄다.

| 시점 | 다시 열면 |
|---|---|
| 커밋 전 | 37개 모두 버전 1 |
| 멈춘 뒤 | **36개는 버전 1, 1개는 버전 2** |

커밋은 실패를 돌려줬는데, 다시 열어 보면 그 커밋의 **절반이 반영돼 있다.** 원자성이 깨졌다. 트리 구조는 멀쩡해서 검사로는 잡을 수 없다.

## 경우 3: 두 번째 분할하다 멈춤 (리뷰에서 찾음)

코드 리뷰가 찾은 경우다. 이미 2층인 트리에서 리프가 또 나뉘면, 커밋은 덮어쓴 리프 `L`, 고친 루트, 새 리프 `R`을 페이지 번호 순서로 쓰고, 마지막에 메타를 쓴다. 메타 앞에서 멈추면:

- 메타는 여전히 "페이지가 N장"이다.
- 그런데 이미 써진 루트(또는 `L`의 옆 포인터)는 파일 끝의 새 페이지 `R`을 가리킨다.
- 다시 열면 트리 검사가 `child page is outside the file`(또는 옆 포인터 오류)로 **열기를 거부한다.**

경우 1과 같은 문제다. 트리가 커져도 분할하다 멈추면 DB가 열리지 않는다. 이 경우도 WAL(#22)로 넘겼다.

## 의미

- 01·02번에서는 커밋이 페이지를 한 장만 써서, 프로세스가 죽어도 "전부 아니면 전무"였다. 4KB 쓰기가 반만 되는 경우는 정전에서만 생긴다(실험 0001). **페이지가 여러 장이 되는 순간 정전이 아니라 프로세스 중단만으로도 깨진다.** 분할의 비용이 여기서 드러났다.
- 설계 결정 5에서 이것을 받아들이고 WAL(#22)로 넘겼다. WAL에서는 커밋의 모든 페이지가 로그에 들어간 다음에야 성공으로 친다. 다시 열 때 로그를 재생하면 세 경우 모두 "전부" 또는 "전무"가 된다.
- #21(정전 실험: 지금은 깨진다)에서 이 도구를 출발점으로 쓸 수 있다.
- 메타를 마지막에 쓴 덕분에 경우 1에서 메타가 "없는 페이지"를 가리키는 일은 없었다. 하지만 키를 지키지는 못했다. 순서만으로는 한계가 있다.
