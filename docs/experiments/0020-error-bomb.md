# 0020. 오류 폭탄 — 오류가 쏟아져도 접속과 데이터는 멀쩡한가

이슈 #34, 설계 `docs/design/0027-type-checks-and-errors.md` E13. 오류 종류를 다시 나눈 뒤, **오류가 끝없이 와도** ① 코드가 늘 제 묶음으로 오고 ② 접속이 끊기지 않으며 ③ 사이사이의 정상 문장이 모델과 같은 답을 내는지 본다.

**비유**: 병원 접수처에 잘못 쓴 접수증을 만 장 섞어 넣는다. 접수처가 잘못된 접수증마다 "주소 칸이 틀렸어요", "이미 접수됐어요"를 정확히 말하고, 창구를 닫지 않고, 그 사이의 제대로 된 접수증은 빠짐없이 처리하는지 본다.

## 어떻게 했나

`cargo run --release -p oakdb-server --example error_bomb -- 10000 <seed>` (`crates/oakdb-server/examples/error_bomb.rs`). 표 `t (id INTEGER PRIMARY KEY, name TEXT)`, id는 0~49라 INSERT가 자주 중복에 걸린다. Apple M3, macOS 27.0.1, APFS, `F_FULLFSYNC`, 실제 디스크.

| 부분 | 무엇을 | 확인 |
|---|---|---|
| A. 서버 | 실제 서버 하나에 **접속 하나**로 문장 1만 개. 10개 중 6개는 오류 문장 25가지 중 무작위, 나머지는 INSERT·UPDATE·DELETE·범위 SELECT | 오류마다 기대한 코드. `0x40` 이상(접속을 끊는 코드) 0개. 정상 문장의 답이 `BTreeMap` 모델과 같음. 끝에 표 전체가 모델과 같음 |
| B. 트랜잭션 안 | SQL 세션에서 `BEGIN` → 같은 섞음 10~49문장 → `COMMIT`을 1만 문장까지 반복 | 실패한 문장은 **그 문장만** 없던 일(설계 0023 T5), 오류 종류와 무관. `COMMIT` 뒤 새 세션이 본 표가 모델과 같음 |

오류 문장은 묶음마다 있다: 문법(줄이 셋인 문장 포함), 지원 안 함(`COUNT(*)`, `t.id`, `IF NOT EXISTS`, `--` 주석, `DROP`, `ORDER BY`), 없는 표·열, 이미 있는 표, 같은 열 두 번, 값 개수, 타입(값, 산술 피연산자, 조건 자리의 값, SET), 값 범위(64비트 밖 리터럴), NULL 기본 키.

## 해석

- **오류 6,400여 개 뒤에도 접속 하나가 끝까지 살아 있었다.** 문장 오류는 모두 `0x01–0x1F` 안이고, 서버는 그 범위에서 접속을 끊지 않는다(`closes`). 오류가 접속 스레드의 상태를 망가뜨리지 않는다.
- **트랜잭션 안에서 오류 종류는 롤백 범위를 바꾸지 않는다.** 타입 오류든 NULL 키든 `0x0C`든 그 문장만 없던 일이 되고, 같은 트랜잭션의 앞뒤 문장은 `COMMIT`에 그대로 남았다(약 330개 트랜잭션).
- A가 B보다 4배쯤 느린 것은 자동 커밋 문장마다 sync를 하기 때문이다(실험 0001: 한 번 약 4ms). 오류 문장은 커밋이 없어 거의 공짜다.

## 실험이 찾은 것: 모델이 틀렸다

처음 돌렸을 때 `UPDATE t SET id = NULL WHERE id = 1`이 "WRONG"으로 수십 번 나왔다. 모델은 "행 1이 없으면 바꿀 것이 없으니 `Affected(0)`"이라고 기대했는데, Oakdb는 행이 없어도 `0x0D`를 냈다.

Oakdb가 맞다. 리터럴 `NULL`을 기본 키에 넣는 SET은 **행을 읽기 전에**(계획 단계) 거절된다(설계 0027 E1의 표, 0022 4-2). "오류는 행 내용과 무관하다"는 약속을 실험의 모델이 먼저 어긴 셈이다. 모델을 고치자 모든 seed가 통과했다. 계산식이 NULL이 되는 `SET id = id + NULL`만 행마다(실행 단계) 검사한다.

## 한계

- 접속은 하나다. 여러 접속이 동시에 오류를 쏟는 경우는 접속 스레드끼리 상태를 나누지 않으므로(ADR 0010) 따로 보지 않았다.
- 서버의 접속별 트랜잭션은 #37 전이라, B는 서버가 아니라 SQL 세션에서 직접 돌렸다. #37이 들어오면 같은 섞음을 서버 위의 `BEGIN`으로 돌릴 수 있다.
